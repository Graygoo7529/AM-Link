# 样本与记忆案例分析

这里长期积累真实数据样本的分析，连接数据特点、记忆设计与后续实验结果。案例说明以中文为主，原始数据保存在被 Git 忽略的 `dataset/data/`；不将整份数据或运行轨迹复制到文档。

## 可持续更新的展示

- [独立网页](./index.html)：在浏览器打开即可浏览，不需要启动服务；导出文件自带展示资源。没有公网部署。
- `view.html`：同一份内容的会话内交互版本，供后续 Codex 会话直接加载。
- [catalog.json](./catalog.json)：数据集状态、原始/处理后特点、八个案例、来源文档和下载入口的唯一展示内容源。
- [手动下载清单](./downloads.md)：尚未完整取得的材料、文件链接、大小及保存位置。

按照用户要求，只持久保存内容和可复用展示，不维护页面选择或已读进度。导出工具自带的浏览器偏好缓存不作为项目状态或实验记录。

## 下次加载与更新

用户说“加载案例库可视化”或“继续分析案例”时：

1. 读取本文件、`catalog.json` 和选中案例文档；获取状态以最近一次实际核验为准。
2. 运行下面命令检查/重建，将 `view.html` 复制到当前会话可写的持久可视化目录，以该副本的绝对路径在最终回复中发出 `visualize` 内容引用。也可直接引用可被当前会话读取的 `view.html` 绝对路径；不要把完整网页 `index.html` 当成内嵌片段。
3. 用户要独立网页时打开 `index.html`。会话内与独立网页使用相同内容，切换与图解都可继续使用。

更新时先核对原文和来源，再编辑案例 Markdown 与 `catalog.json`，最后重建。不要直接修改生成的 `view.html` / `index.html`，也不要把新下载的数据未经检查就标成可用。

仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -m casestudies.build --check
.\.venv\Scripts\python.exe -m casestudies.build --web
```

构建只需要 Python 标准库；网页导出使用本机 visualize 技能的 `scripts/render.py`，自动发现已安装版本，也可传 `--renderer <完整路径>`。没有该技能时仍可运行不带 `--web` 的命令生成会话片段，已有网页不受影响。已导出的 `index.html` 打开时不依赖该技能或 Python。

`--inline-output <当前会话目录/案例库.html>` 可同时输出会话副本。未加该参数时只更新仓库内的展示。来源、案例 ID 和 HTTPS 链接会在构建时检查。

## 共同分析口径

1. **来源事实**：固定来源版本、文件哈希、记录/任务/片段 ID，区分原文、中文转述和自己的推断。
2. **数据准备**：说明原始字段如何变为历史、任务输入与评估标注；不能把 gold answer、rubric、偏好标签写入 Add。
3. **方法示意**：说明 Add 应保留的结构、Search 应提供的证据及预期回答边界。示意不是某系统的实测输出。
4. **真实实验**：另记 system/version、pack、plan、trace、配置和费用。未运行写“未运行”，无证据标签写“不适用”，不能填 0 分。
5. **失败归因**：分清数据本身、准备、Add、组织/索引、Search、上下文裁剪与 Answer；内部行为不可见时，不凭外部结果断言内部故障。
6. **比较单位**：同历史的不同 QA 版本不算独立测试历史；同用户/人物/共享背景按组切分。报告单条证据召回和完整链覆盖，不用一项代替另一项。

这里的“正确处理”指证据充分且不越界的参考方案，不要求所有系统采用相同的存储结构或图数据库。
