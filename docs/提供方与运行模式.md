# 提供方与运行模式

## 运行模式

Smoke/降级模式设置 `AML_LLM_ENABLED=false`、`AML_EMBEDDING_ENABLED=false`。Add 仍同步提交 raw、working memory 和 FTS，Search 只返回 lexical/graph 可找到的证据；该模式不满足主办方 Full checklist 的 Add/Search 模型项。

Full 候选模式必须设置 `AML_LLM_ENABLED=true`，模型配置只能是 `gpt-4o-mini`。`AML_EMBEDDING_ENABLED=true` 用于提高同义和长距离召回，但不是官方 Add/Search schema 的字段，不改变外部协议。

`AML_ENRICHMENT_MODE=sync` 是默认模式；`async` 模式在 raw/working/FTS 硬提交后立即返回，由持久化 enrichment worker 执行 maintenance/embedding。job 状态保存在 SQLite 中，进程重启时超过 5 分钟的 running job 会回收到 pending 后继续消费；Add/Search 的可选阶段分别受 `AML_ADD_DEADLINE_SECONDS` 和 `AML_SEARCH_DEADLINE_SECONDS` 限制。

本地代理联调可设置 `AML_LLM_MODEL=gpt-5.4-mini` 和 `AML_ALLOW_NONOFFICIAL_LLM_MODEL=true`；默认关闭该开关，防止调试模型误进入竞赛提交。`gpt-5.4-mini` 的真实 JSON smoke 已通过，但不能用于宣称 Full 合规。

## gpt-4o-mini 适配

适配器使用 OpenAI Chat Completions 兼容协议：

```text
POST ${OPENAI_BASE_URL}/chat/completions
Authorization: Bearer ${OPENAI_API_KEY}
model: gpt-4o-mini
response_format: json_object
```

OpenAI 官方模型页确认 `gpt-4o-mini` 支持 Chat Completions 和 Structured Outputs：[gpt-4o-mini](https://developers.openai.com/api/docs/models/gpt-4o-mini)。

当前 Full 候选配置将 `OPENAI_BASE_URL` 指向 `https://api.zhizengzeng.com/v1`。智增增文档声明该地址接受 OpenAI 格式请求；真实最小探针已确认 Bearer 和 JSON mode 返回 HTTP 200，响应体的 `model` 字段明确为 `gpt-4o-mini`。完整 Add/Search 与 5 Add / 6 Search LoCoMo 切片均已跑通，容量验收仍按下列项目执行：

1. `/v1/chat/completions`、Bearer 和 JSON mode 可用；
2. 返回模型确实是 `gpt-4o-mini`，没有静默替换；
3. 速率、价格、账单上限和 72 小时评测容量足够；
4. 代理的数据留存和转发范围符合赛事 30 天删除要求。

若任一项无法确认，应把 `OPENAI_BASE_URL` 改为可信且获准的数据处理端点；业务代码无需修改。旧 Sublyx 代理仅保留在历史调试记录中，不再是默认运行配置。

## embedding-3 适配

适配器按智谱官方协议调用：

```text
POST https://open.bigmodel.cn/api/paas/v4/embeddings
Authorization: Bearer ${ZHIPU_API_KEY}
model: embedding-3
dimensions: 512
input: string[]
```

智谱文档说明单批最多 64 条文本、每条最多 3072 tokens、维度范围 256 至 2048；当前实现使用 2400 字符分块、200 字符重叠、512 维，并再次对向量做 L2 归一化：[Embedding-3](https://docs.bigmodel.cn/cn/guide/models/embedding/embedding-3)。

向量表主键包含 memory ID、模型、维度和 chunk number，查询同时约束 user ID。tombstone 会删除向量；离线重建在新向量全部计算成功后事务替换旧索引。

## 调用与成本边界

首次 Add 进行一次 `gpt-4o-mini` maintenance；生成模型把可选列表返回为 `null` 时确定性规范化为空列表，可选 confidence 的 `null` 恢复为默认值。代理若把 plan 级 `tombstone_memory_ids` 错放进单个 fact，仅在该值为空时移除；非空值和其他未知字段仍严格拒绝。只有其余 JSON 无法通过 Pydantic schema 时，才携带不含正文的字段路径/错误类型做一次有界 schema retry。HTTP/provider 错误、越界 mutation 和第二次非法 schema 不在该层继续重试。默认阈值为 1，兼容原有每 Add 行为。设置 `AML_MAINTENANCE_EVENT_THRESHOLD` 或 `AML_MAINTENANCE_CHAR_THRESHOLD` 后，maintenance 会在 watermark 之后累计事件达到任一阈值时批量处理 pending raw events，source ordinal 会在本次模型输入内重新编号。若启用 embedding，还会先用本次事件做一次旧记忆相关性查询，再对本次 raw 和结构节点分块建索引。embedding 请求数为 `1 + ceil(新增分块数 / 64)`（没有旧向量时相关性查询仍会执行）。相同 Add 幂等重放不再调用外部服务。

每次 Search 最多进行一次 `gpt-4o-mini` query plan。首次单文本 embedding 用于初召回；planner 确实产生扩展词时，再对“原 query + options + 扩展词”执行一次单文本 embedding。planner 前一跳 inspect、最终两/三跳 link 扩展与特征/RRF 均在本地执行，不产生额外模型调用，也不使用 pi SDK 或自由 Agent 循环。

async 模式不会改变模型调用次数，只改变调用发生在 Add HTTP 请求内还是持久化 worker 内；请求重放不会重新创建相同 enrichment job。

30 天成本不能按在线时长直接估算，应按调用量计算：

```text
LLM 成本 = Add 调用输入/输出 tokens + Search 调用输入/输出 tokens
Embedding 成本 = 新增索引文本 tokens + Search 原 query tokens + 可选扩展 query tokens + 重建 tokens
基础设施成本 = 服务器 + 持久盘 + 备份 + 公网流量
```

代理的实际单价目前未知。智谱文档当前展示 embedding-3 为每百万 tokens 0.5 元人民币；预算仍应以正式账号账单和限额为准，部署时设置余额告警与每日调用指标。

## 故障语义

| 阶段 | 故障 | 行为 |
| --- | --- | --- |
| raw SQLite 事务 | 失败 | Add 不返回成功，由客户端重试 |
| Add 模型 | timeout、429、5xx、非法 JSON/schema | 记录 failed maintenance；raw 仍已持久化且可检索 |
| Add embedding | timeout、429、5xx、维度错误 | 保留 FTS；不写入半批向量 |
| Search 模型 | 任意提供方错误 | 使用原 query/options 做 lexical 检索 |
| Search embedding | 任意提供方错误 | 使用 lexical + 已有 links |
| Markdown 投影 | 文件系统错误 | 数据库真源不回滚，记录脱敏错误 |

failed maintenance 不会被普通 request 重放隐式重复计费；运维人员确认提供方恢复后，可用 `aml_memory.retry_maintenance` 对指定 `user_id + request_id` 做一次显式 claim/retry。

一般 enrichment job 失败后会进入 `failed` 并等待退避；async worker 不会忙循环。维护失败可用显式 retry，raw 事件和 FTS 始终保留。

提供方错误日志不写响应正文、prompt、用户消息或 Key，只记录 error type、request ID 和 user ID 哈希。

## 密钥操作

`OPENAI_API_KEY`、`ZHIPU_API_KEY` 和 `AML_API_KEY` 只从进程环境或部署平台 secret manager 注入，不写入 `.env.example`、README、Dockerfile、镜像层或数据库。通过聊天、工单或日志公开过的 Key 应轮换后再用于正式评测。
