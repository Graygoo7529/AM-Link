# 连续检索与交付预算改进执行计划

日期：2026-10-31

## 目标

在不改变 Add/Search 对外契约、不增加 Search 内 Answer、不恢复自由 BFS 的前提下，修复当前真实运行中暴露的三类系统损失：

1. 多轮 Select 之间缺少模型可见的连续语境；
2. 稳定 ref 只存在于观测映射，模型主要依赖本轮 `[N]` 编号；
3. Select 的阅读预算与最终装箱预算脱节，选中材料可能在交付时被省略。

同时收敛 Reflection 的来源和数量协议，并把补充 Query 的用途和进入路径保留到观测与模型语境中。

## 设计约束

- Add 成功仍只表示原文、episode、索引和成功凭据已原子提交；Reflection 可以不完备，但不能留下半批 mutation。
- Search 仍只读已提交 MemoryItem/episode/note，返回原文证据；不读取 WorkingMemory，不运行 Reflection，不生成答案。
- 不使用 gold、参考答案或特定案例关键词改变运行时行为。
- 不增加内部重试；工具协议错误必须整次操作失败并保留清晰观测。
- 预览仍是原文片段，不能变成模型生成的事实摘要；装箱不改写原文。
- 所有新增状态都只存在一次 Search 调用内部，不改变数据库持久化结构。

## 实施阶段

### 阶段一：连续性账本和可见引用

新增确定性 `reading continuity` 叙事，记录问题任务形状、上一轮已选范围、补充 Query 及其用途标签、`read_more` 来源和新候选进入路径。提醒模型检查主体、时间和比较两侧等必要信息；程序不判断某个证据槽已经满足，也不虚构模型先前的推理。

每个模型可见候选同时显示本轮 `[N]`、稳定语义 ref、自然标题、角色、说话时间、来源路径和原文/预览内容。保留现有工具 positions 结构，先不引入 `drop` 等新原语。

末轮 Select 将上一轮选择标为既有证据，新增候选标为新材料；提示默认保留已覆盖的必要证据，只有重复或冲突时才替换。观察 `carry` ref 保留率、补读增量和替换情况。

### 阶段二：Query 分支和阅读路径

把 Select 返回的补充 Query 包装为带用途的内部分支记录。用途只来自当前问题形状和模型返回的 query 文本，不重新调用模型生成计划。

在候选正文和观测中区分 direct query、branch query、note、adjacent、requested read 和 context closure。合并候选时保留分支标签，并继续对不同入口做公平交错，避免某一路径占满预算。

### 阶段三：交付预算前移

为每个阅读单位计算确定性的预计交付成本，包含来源标题、角色、时间、顺序说明和正文。Select 输入显示候选成本、携入成本与总预算；单元成本按各自来源头估计，同组共享头时会高估，不冒充实际已用或剩余量。提醒末轮保留必要信息、冲突两侧和时间条件。

先不增加新的 LLM 装箱调用，不截断原文。pack 仍负责确定性复制和来源标注，但观测额外记录预算预估、最终省略原因和被省略单位的路径。

### 阶段四：Reflection 协议稳定

验证整理工具的可接受输出：note 必须引用当前 batch 的合法 episode，标题/正文在 schema 校验，条数/来源编号在提交前校验；同来源近似 note 在提交前确定性去重；不合法时整批不提交。额外 schema 数量限制和提示变化只有实测支持时才保留。

允许一个 note 连接多个当前 batch episode，但每个 note 的模型叙事必须能在这些原文中找到支持。保留旧 note 只作为检索背景，不作为新 note 来源。

## 验证计划

1. 先运行完整本地回归和针对连续性、稳定 ref、预算估算、分支来源、Reflection schema 的单元测试；
2. 用合成 fixture 检查多轮 Select 的输入是否包含上一轮账本、候选是否保留 stable ref、预览是否仍为原文；
3. 在同一套 26 历史/100 题上建立新的独立运行命名空间，完成 780 Add、100 Search 和本地 Answer；
4. 分阶段比较 Query 召回、首轮 Select 保留、末轮 Select 保留、pack 省略、Reflection 完成率和 Answer 使用证据，不把某一阶段指标直接称为整体准确率；
5. 若连续性和预算改动没有稳定减少跨轮丢失或装箱省略，则撤回对应改动，不引入更复杂的图搜索或额外模型调用。

## 验收标准

- 对外 Add/Search 请求和响应格式不变；
- 现有回归测试全部通过；
- 多轮 Select 的模型输入能解释既有证据、新材料和补读用途；
- 模型可见 ref 与观测 ref 一一对应；
- 预览不会被误当作交付正文；
- pack 的字符预算不会静默丢失，所有省略都有观测原因；
- Reflection 非法工具输出不产生部分写入；
- 真实 100 题结果按阶段分别报告，并保留完整 I/O 和失败记录。

## 部署前收敛（2026-10-31 用户确认后的执行范围）

1. 固定唯一生产版本 `0.3.4-continuity`，保留可读引用、跨轮选择记录、分支路径与成本提示。没有新增模型调用，工具仍仅选局部整数编号。
2. 撤回未通过的三种 Select 区间协议和条数硬上限。保留研究输入、输出与源码快照；不留开关或失败兜底。恢复此前的 Reflection 提示和工具形状，保留提交前校验和新观测；本轮更严格提示/schema没有证明稳定性改善。
3. 修正分支来源标注遮蔽 note 导航、重复命中丢分支路径和补查用途未进入 Query 观测的问题，然后冻结源码。
4. 全量回归；在最终源码上以 LoCoMo、PerLTQA、CL-bench 三份完整公开历史重建空库（38 Add、15 Search），不将它们与百题或裁剪组件混合计分。额外调用上限1,050次、输入1,500万字符；连同已有本轮调用在6,200次/6,000万字符内。
5. 准备最小源代码发布包、依赖版本清单、Linux 单进程服务配置、独立环境示例和接口 smoke 工具；检查打包内容及本机真实 HTTP 契约。包内不带数据库、模型I/O、研究数据或凭据。
6. 核对最新官方契约，更新 DESIGN、入口文档、实施报告与 AGENTS。执行计划逐项记录“完成、撤回、尚未验证”的范围。实际服务器安装、TLS、吞吐和官方 smoke 留给部署阶段，不能以本机验证代替。

收敛目标是一个可部署、边界清楚的工程版本。百题完成并不证明选择完整性；提示预算仍有装箱省略，Reflection仍有长尾工具错误。连续性字段作为如实呈现的阅读状态保留，不宣称它已经提高准确率或减少漏选。
