# 第三版清洁重构执行计划

制定：2026-10-29；按真实诊断收敛：2026-10-30。当前设计见[根 DESIGN](../../DESIGN.md)，实测见[核对报告](../doing/2026-10-29-clean-rebuild-implementation.md)。

## 目标与原则

以稳定接收、证据可见、代价有界为先，保留 AM-Link 的关联记忆理念，但把关联首先落在可验证的来源链接上。Reflection 负责建立目录，Search 负责问题驱动的证据组合；不让一个小模型在写入时维护整张语义图。

二期26/75暴露任务分解的问题，不能靠更长时限或更多修订轮解决。此次删除旧草案/审查/关系写入流程。源码与设计归档；原始数据集和案例文档保留，新实验从新库开始。

## 设计取舍

1. 原文切成保真 episode，每段必有词项及 v4/1024 向量，再原子接收；不采用“向量失败仍接收”的降级。
2. WorkingMemory 是已索引原文的待整理登记。会话边界或积累门槛触发，每批一次模型调用，每次 Add 最多两批；失败记 unorganized，不自动反复修订。
3. Reflection 输出只有标题、短正文和来源编号。统一 note 类型，去掉模型节点分类；旧记忆不变，只新增导航和来源链接。
4. Query 混合 BM25/embedding；Inspect 展开原文，反链扩展只走真实来源；Select 读取完整卡片，按需提出最多2条具体缺口查询。最多2轮 LLM；最终工具只输出有序证据编号。
5. 同一可见范围用于 Select 和最终输出，保留原时间与角色；返回原文，不返回未经确证的派生摘要。
6. 遗忘独立于 Reflection，在原子接收内生效；候选先逐条独立核对同一主题再提交；当前整消息粒度和直接指令入口仍是待验证局限。
7. 一个默认方法，无内部重试、隐藏开关或旧实现备用路由。研究调用设预算，生产进程不因累计调用计数永久停机。

## 验证和停止条件

- 必要接收失败或原文覆盖缺口：暂停扩大，查清原因。失败Add的历史不能算完整。
- 必要 Query/Select 失败：保留原始输出，区分模型协议和网络，不通过重试美化成功率。
- 结构化整理协议完成不等于笔记准确；空笔记、虚构摘要、错误归属分别审读。
- 不能只用source ID召回衡量多条重复叙述；同时核对必要金额、主体、时序和推理中间事实。
- 首轮四公开锚点有明显协议问题时，仅做小范围设计修订再新库重跑；不混入旧版本分数。
- 首批完整历史若仍缺证据或存在遗忘误删，不直接进入正式Smoke/Full。
- 没有部署、自动Git提交、改变私有凭据或恢复旧库的步骤。

## 后续方向有先后

先以完整历史定位损失发生在候选容量、Select或最终组合哪个位置，再决定是否需要扩大候选、分组交付或增加一轮查询。仅当能用同一完整历史证明增益时，才增加新的结构。不要把旧六类节点、图审查和自由loop整体加回来。

旧计划中“embedding可失败后降级”“失败批遇到新Add再重试”“Search不调用模型”属于本轮已丢弃的早期骨架，均不再是当前执行方案。
