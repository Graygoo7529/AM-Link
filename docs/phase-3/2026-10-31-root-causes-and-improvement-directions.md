# AM-Link 当前根因归纳与改进方向

日期：2026-10-31

这份文档从 100 题真实运行中提炼系统问题，不针对某一道题增加关键词、固定路径或答案提示。改进目标是让 Add、Reflection、Query、Inspect、Select 和 Search 仍然保持当前职责，同时减少证据在模块之间转换时的语义损失。

## 先固定问题边界

当前 Search 的职责是从已提交记忆中返回证据，Answer 由评测方负责。Search 有一个自然语言 `query`，并根据问题文字加入补集、比较、多项和指代等任务形状提示；它没有独立的“答案是否已经足够”的模型判断，也不应该在 Search 内生成答案。

当前 Select 不是完全看不到内容。首轮通常同时收到完整的已披露原文和被截短的原文预览；选择预览或 `read_more` 后，系统才把相应原文加入下一轮。问题出在语义连续性：程序传递了 `carry`，但模型没有收到上一轮的查询目的、证据覆盖情况和补读原因。稳定 ref 也主要留在观测映射中，模型正文主要使用本轮 `[N]` 编号。

因此需要区分三种损失：

1. **召回损失**：Query 或入口披露没有提出相关来源；
2. **阅读损失**：来源已经进入候选，但预览、候选预算或 Select 没有让模型读到足够正文；
3. **交付损失**：模型已经选中证据，但最终装箱因集合或字符预算没有返回。

Reflection 还有第四类问题：导航 note 的工具 schema、来源列表和条数限制在长尾输入上偶尔失败。它不应使原始 Add 失败，但失败会降低后续 Query 找到跨消息桥接材料的机会。

## P0：建立检索连续性账本

这是最直接、风险最低的改进。它不增加规划模型调用，也不改变对外 Search 返回结构，只把已有状态转换成下一次 Select 能读懂的自然叙事。

每次 Select 的输入在 `Question` 和候选正文之外，增加一个短的连续性区块：

- 当前问题的证据槽：主体、属性、时间/状态、比较或排除项；
- 上一轮已经阅读和选择的原文范围；
- 每个范围支持哪个槽，或者只是邻文/背景；
- 已请求的 Query、`read_more` 和它们要补的缺口；
- 新候选来自原始 Query、补充 Query、邻接还是 note 导航；
- 仍未满足的槽，以及本轮可用于补足它们的候选。

每个模型可见候选同时显示：本轮位置、稳定语义 ref、自然标题、来源/角色/时间、路由说明和原文片段。`[N]` 继续作为工具调用位置，稳定 ref 负责跨轮识别同一来源；两者必须在同一条叙事中出现。

末轮 Select 不应把首轮材料当作普通新候选。默认语义应是“保留已覆盖的必要材料，再决定新增或替换”；如果新材料替换旧材料，观测记录替换关系和原因。实现上可以先采用自然语言标记和现有 positions 工具，避免立刻扩展复杂 schema；只有实测仍大量错误替换时，才考虑增加显式 `drop` 原语。

验证重点不是某一道题是否答对，而是同一 Search 中：已选范围是否在后续输入仍可识别、补充 Query 是否带来新增证据、末轮是否无故丢失已满足槽。对照指标包括跨轮 ref 保留率、槽覆盖变化和新材料增量。

## P0：在 Select 前显式计算交付预算

当前模型看到的是阅读预算，最终 `pack` 使用的是另一套带来源标题、时间和顺序说明的预算。模型可能选出在阅读阶段合理、但无法完整交付的集合，导致最终 76 个 evidence group 被字符预算省略。

改进方向是把“可读预算”和“可交付预算”分开显示但统一计算：

- 每个候选给出估计的交付字符成本；
- 显示已经保留的成本和剩余预算；
- 为同一来源的相邻单位合并估算，避免重复计算标题；
- 末轮优先保留支持未满足槽、冲突两侧和时间条件的单位；
- 装箱前输出预计省略项，交给 Select 再做一次同一调用内的删选。

第一版不引入新的 LLM 装箱调用，也不截断原文句子。先让 Select 看到真实成本，观察字符省略是否下降；如果仍需要模型参与装箱，再增加只返回 ref/range 的受限工具调用，禁止生成或改写证据正文。

## P1：让 Query 分支有可解释的合并语义

当前 Query 可以产生补充问题，但合并后模型主要看到新候选，未必知道它们分别来自哪个检索目的。改进不是增加更多 Query，而是给每个分支加一个简短用途标签，例如“补时间条件”“寻找比较的另一侧”“展开指代对象”。标签由已有 Select 输出的 query 目的生成，不需要额外规划模型。

合并时保留三层来源：原问题、补充 Query、邻接/来源路径。Select 可以据此判断新候选是独立证据、桥接材料还是重复背景。合并顺序继续保持多入口公平，不让某一个宽泛分支占满候选预算。

## P1：把 Reflection 稳定为来源导航维护

Reflection 的长期职责应是构建可检索入口，而不是生成脱离原文的事实摘要。建议保持当前小批模型调用，但在工具层进一步收窄输出：

- note 必须引用本批允许的 episode ref；
- note 文本有明确长度和条数边界；
- 同一来源的近似 note 在提交前做确定性去重；
- schema、来源和数量不合法时整次整理不提交部分结果，并记录明确错误；
- 原始 episode 和索引先保持可用，整理失败不影响 Add 成功。

为了改善多跳问题，可以允许 note 连接多个已有 episode 的共同主题，但 note 必须把每个主题陈述绑定到对应原文来源。这样得到的是导航桥，而不是未经证实的关系图或答案缓存。

## P1：改进阅读单位和邻接的语义提示

当前连续阅读块已经比逐句片段稳定，但邻接内容仍可能被模型误认为独立命中。候选正文应始终区分：

- 直接 Query 命中；
- note 来源展开；
- 同消息相邻单位；
- 同会话即时前后文；
- 为解决代词而自动闭合的上下文。

这些不是不同的证据可信等级，而是不同的进入路径。区分路径可以帮助模型理解为什么材料被展示，减少把背景句当成新的事实，也便于观察哪个路径实际带来增量。

## 暂不引入的方向

暂不恢复自由 BFS、复杂关系图、固定节点类型配额或 Search 内 Answer。它们会增加状态和预算维度，当前实测还没有证明能解决“候选读到但末轮丢失”的主要问题。也暂不为某一类题增加硬编码关键词或固定证据数量。

## 推荐执行顺序

1. 先实现连续性账本、模型可见稳定 ref 和 Query/补读来源叙事；
2. 在同一 100 题套件上做离线投影，检查末轮保留率和证据槽覆盖；
3. 再把交付字符成本前移到 Select，重测装箱省略；
4. 最后处理 Reflection 工具协议长尾，并观察多跳入口是否增加；
5. 每一步都分别报告召回、Select 保留、装箱交付、Add/Reflection 协议和 Answer 使用情况，不把某个阶段的改善写成整体准确率提升。
