# Search 证据闭合与任务意图改进计划

## 背景与根因

2026-10-30 的固定候选和完整历史运行已经把问题从“有没有召回”推进到“模型是否同时看见并能交付完整证据”。真实轨迹中反复出现三类现象：

1. Query 能找到相关原文，Select 也能选到一句回答，但这句话使用代词、简短确认或省略主语，解释它的相邻问句/标题没有随选择结果交付。典型表现是续读电影问题时保留了“我看过”，却丢掉了它回答的具体电影；宠物历史中读到时间，却在末轮选择时丢失同一事实的限定。
2. “除此之外/还有哪些”“比较两次变化”“当前状态与旧状态”这类问题的证据形状没有在 Select 输入中被明确表达，主题词较强的候选会占满阅读空间，模型缺少一种稳定的任务检查方式。
3. Reflection 已经阻止完全相同的 note，但同一批次或新批次里语义高度相似、来源相同的导航 note 仍会累积，挤占真正有增量的导航入口。

这些问题属于模块职责本身：Query 负责入口，Inspect/相邻上下文负责可读证据，Select 负责语义取舍，装箱负责忠实交付；不能靠 Answer 猜测缺失内容，也不能把某一道题的答案写进提示词。

## 本轮实施范围

### P0：选择结果的上下文闭合

在 Select 结果进入下一轮或最终装箱前，检查每个已选原文单元是否包含常见的指代、简短确认或承接表达。若同一 episode 中存在紧邻的前一个原文单元，则把它作为 `context_closure` 一并带入；同一 episode 没有前文时，只从已经由 Inspect/邻接披露的同会话即时前一 episode 取一个原文单位。该单元仍是逐字原文，不能改写成推断。

- 闭合优先同一 episode；跨 episode 只使用已经披露、同会话且有明确即时邻接的前一来源，不跨被遗忘范围，也不把相似主题当作相邻事实。
- 闭合结果先作为 carry 进入末轮 Select，使模型可以重新取舍；末轮之后再次执行同一确定性闭合，保证最终交付不会把解释性前文丢掉。
- 观测账本明确区分 `model_selected` 与 `context_closure`，并记录触发它的原文范围，便于判断证据是在召回、Select 还是装箱阶段消失。
- 同一 episode 的闭合单元与原选单元属于同一 passage group，不额外消耗 `top_k` 组名额；已披露的相邻 episode 闭合会按普通组计数。所有闭合仍受最终字符预算约束，若预算不足则记录明确的 `characters` 省略。

### P1：在现有 Select 调用中表达任务形状

不新增 Query 模型调用，向现有 Select 的自然语言上下文加入由问题本身推导的任务提醒：

- 识别“除此之外/其他/除了”一类补集问题，要求寻找与已点名主题不同的独立发生，而不是停在主题最高的条目。
- 识别比较、变化、前后状态和日期问题，要求同时保留比较两端、状态限定和时间表达。
- 识别代词和承接句，要求把可解释所选句子的相邻原文视为必要背景。
- 识别清单、总量和多部分问题，要求保留不同发生或不同对象，不能用一段泛泛讨论代替具体事实。

提醒只描述问题的证据形状，不包含任何数据集答案、实体名或 gold 信息；模型仍通过已有 `positions/queries/read_more` 工具决定具体材料。Search 的标准返回仍然只是结构化 MemoryItem 的原文结果，不加入 Answer 或“已足够”判定。

### P1：Reflection 近似重复控制

保留现有 tool schema 和一次整理边界，在提交 note 前增加保守的近似重复判断：只有当新 note 与既有 note 具有相同来源且 token 集高度重叠时才跳过；不同来源或仅主题相似的事实仍保留。这样可以减少导航噪声而不把跨事件的真实重复词误删。

## 验证与验收

1. 运行现有完整测试，并新增闭合单元、闭合观测和近似 note 控制的单元测试。
2. 使用合成 fixture 验证：选中代词回答时会携带前一个问句；跨 episode 不会闭合；最终装箱记录闭合来源；预算不足仍返回可审计省略记录。
3. 检查 Select 输入包含补集、比较、状态、代词和多部分任务提醒，且不含具体 gold 事实。
4. 检查 Reflection 的相似 note 只有同来源高重叠时才被丢弃，跨来源同主题仍可保存。
5. 本轮不宣称真实准确率提升。若要使用新增真实模型调用，应在代码与本地测试通过后另行冻结载荷并取得明确授权；本轮先完成可审计的实现。

## 实施核对

已完成：

- `amlink/reading.py` 增加同一 episode 内的 `context_closure`，仅为代词、简短确认和承接句补充紧邻前一原文单位；`ledger`保留闭合原因和触发范围。
- `amlink/engine.py` 在 Select 输入中加入补集、比较/状态、多项和指代的任务形状提示；没有添加答案事实或新的模型调用。
- Reflection 提交前增加同来源、高 token 重叠的保守近似去重；不同来源不因主题相似而合并。
- 最终装箱观测分开记录 `model_selected`、`context_closure` 和预算省略；Search 的标准返回、Add 原子语义、无内部重试边界不变。
- 版本更新为 `0.3.3-evidence-closure`，`DESIGN.md` 已同步流程图和语义说明。
- 本地 `.venv\Scripts\python.exe -m pytest amlink/tests -q -ra`：63 passed，2 个既有 pytest 缓存目录权限警告；没有真实模型调用。

限制与后续验证：

- 闭合只处理同一 episode 或已披露的同会话即时前一 episode；更远的跨 Add 问答仍依赖已有 Query/邻接披露和 Select，不能宣称所有代词都已解决。
- 任务形状提示改善模型的检查入口，但没有强制模型提出补集 Query；需要在获得新的真实调用授权后，用新的完整历史验证召回覆盖和答案效果。
- 近似去重采用同来源门槛，跨来源的重复事实仍可能形成多个 note，这是保守避免误删的取舍。
- 历史运行、研究分母和默认数据库没有改写或清空。


## 真实验证核对

用户授权后完成了四个独立公开案例运行，完整记录见 docs/doing/2026-10-31-evidence-closure-real-validation.md。closure31-r16-e1、closure31-r17-e1、closure31-r18-e1、closure31-r19-e1 共 139/139 Add、4/4 Search，均使用真实 text-embedding-v4/1024 与 gpt-4o-mini。Add/Search 没有协议失败；r16–r18 的 evidence recall@5 分别为 0.333、0.2、0.4，r19 没有评估侧证据目标。

本轮核对结论：

- P0 context_closure 已真实触发并被账本区分；r16 的时间比较得到正确诊断 Answer，但闭合仍会与跨 episode 的 top_k 预算竞争。
- P1 任务形状提示已进入 Select 输入，但没有产生新的 Query；r17 的补集和 r18 的对象类型仍出现候选覆盖不足，因此不能把提示变化称为召回改进。
- P1 同来源近似去重没有引起协议错误或 Add 失败；四次运行的报告 duplicate_rate 均为 0，但本轮题目不足以证明导航 note 的语义增量。
- r19 的真实 Answer 仍把旧实例适用条件套到新实例，说明下一轮应先改善规则/旧实例/当前条件的来源叙事，再评估更强 Answer。

因此，本计划的工程实施完成，方法验收未完成。下一轮应验证有限证据槽查询、共同证据组的预算和适用范围叙事；不改写本轮运行分母，也不为单个案例加入答案特例。
