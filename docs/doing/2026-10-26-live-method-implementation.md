# 原文证据集合与分步Reflection：实施和真实观察

用户提交基线为`2490307`。本轮已把新的Select、分步Reflection、来源对应与局部修改接入唯一主链路；删除`reflection_staged`开关、旧整包提交以及未调用的旧装箱函数。没有把新方法做成默认关闭的实验。174项回归通过，无部署、无提交/推送。

结论是：原文片段的选择和传递已有具体改善，局部草案可以完成真实写入，人物图也出现一次有效的反向导航；长历史整理、关系语义及重复节点仍不稳定，整体方法没有验收。完整数据见[运行台账](./2026-10-26-live-run-ledger.md)，形象说明见[五个案例观察](../../casestudies/2026-10-26-live-method-cases.md)，当前流程见[根DESIGN](../../DESIGN.md)。

## 已成为当前方法的改变

### Select选择互补原文，再保留选中范围

问题先于材料进入模型。候选多于5个时执行Select；同一个Reference中的不同原文片段独立呈现，含语义ref、类型、角色和来源时间，最多24张一页。模型说明各段直接提供的证据贡献，再输出有序位置；分页后统一Select，最后合并同ref并保留实际选中的片段。

这些片段直接进入后续Context和最终证据组，不重新选另一个窗口，也不机械截成520字符。完整范围/hash/遗漏记录保留在观测中，避免同一份元信息在模型输入里重复数次。模型已参与证据集合的组织；最后确定性展开原文并补来源/路径，没有增加能自行改写证据的生成器。

反例仍需保留：提前Select、只把问题置前、6引用一页、逐候选额外评估、先列信息需求均没有单独稳定解决问题。这些变体只有研究档案，没有额外执行开关。

### Reflection从一次大输出变为可验证的局部草案

当前唯一流程是节点草案→具体旧材料待办→必要局部patch→关系草案→来源审查→重新校验→原子提交。patch只修改缺陷节点，其余保存；材料读齐后validate保存草案，不重新生成整批。完全相同的旧节点归并后形成的冗余自环会去重，直接提出的自环仍然非法。

提交前每页最多审查4项，先审查节点，再把修改后的端点给关系审查。模型可修订节点的正文、来源、已有时间字段，或撤销未支持的提案；关系工具只允许保留/撤销。来源以实际可见原文位置选择，系统展开出处、范围和版本。角色、发言日期参与审查；发言时间不自动等于事件时间。审查后再次检查身份、来源、类型和材料闭合，再写入数据库。

这解决了“能发现错误，却只能整批重写”的操作问题，但不是一个可靠的事实裁判。C2中审查仍把“纳税规则与申报流程”误认成supersedes，必须作为真实失败记录。

### 读到的材料必须改变下一步决策

最新C2轨迹证明，旧版本即使展示了来源页，待办也可能永远不清除：它只实现了正文已读检查，没有实现冲突两侧来源的完成检查。现在材料待办与提交门槛共用`missing_material`，来源页入口指向真正的raw来源；有关来源读入后保留至验证。

真实复验从轮数耗尽变成了另一类边界：`protected_workspace_budget`。这表示旧材料保护和草案大小的组合仍可能超出工作区容量；没有通过移除必须材料或假成功来绕过。下一项研究应缩小一次需要共同验证的语义单元，同时保留完整来源关系，不能只提高轮数。

Search中的可读引用新增实际入/出边数量及关系类型，让模型知道何处有可探索联系。仍由模型选择Inspect/Backlink/Stop，不固定按kind走图。

## 尚未解决的核心问题

1. **长历史整理的共同材料过多。** 错误supersedes、宽泛节点和大量旧来源会一起扩大保护语境。当前明确失败；需要围绕一组相关陈述组织更小的验证与提交，而不是让一个长草案同时协调全部旧记忆。
2. **来源可见不等于语义支持。** 位置选择杜绝了抄错引文，但模型仍可能选择不支持陈述的来源，或把“更具体”理解为“替代”。应逐项核查陈述、条件、主体和关系，而不是以schema或来源ID合法作为正确性依据。
3. **重复节点会污染候选集合。** LM4旧库仍含多个车灯fact；新Select能够补金额，但尚未消除重复节点与不完整的直接来源。实验副本没有自动修复旧图。
4. **有效图路径的证据仍少。** 本轮有一次自然Backlink成功、更多零边窗口和失败完整历史。两跳以上收益需要真实、正确形成的关系图支持，不能人为造边后冒充方法效果。

这些是下一轮方向与验收问题，不是另有一套默认关闭实现。当前代码始终使用本报告的主方法。
