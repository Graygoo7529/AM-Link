# 从真实模型输入理解断点：引用、阅读与 Answer

2026-10-30。延续用户确认的原则：从模块职责解释现象，不为某道题追加规则。基线仍是 `5a9146a` 加此前未提交的 reading 改进；本轮只修改研究侧 Answer，未修改生产 Add/Search、配置、数据库或旧实验结果。执行与后续计划见 [计划](../phase-3/2026-10-30-narrative-and-answer-plan.md)。

## 结论

原文保存、找到相关材料、选择完整证据、理解证据并作答，是四种不同能力。当前应优先改善**引用的可操作性、阅读单位的粒度和未读候选的续接**，同时用更强的本地 Answer 减少阅读理解能力带来的混淆。没有证据表明需要恢复复杂图构建或多轮整理审查。

本地 Answer 已改为 `gpt-5.4`、`reasoning_effort=medium`，单次120秒、8192 completion tokens（包括推理消耗），不重试、不自动切模型。方法内部仍是 `gpt-4o-mini` 和 `text-embedding-v4`。官网明确由平台负责 Answer/Eval；本轮没有核实官方 Answer 的具体型号，不能把本地选择说成官方配置。

## 一、Add：来源编号正确，不代表笔记语义正确

第三版已经把整理职责缩小为“建立原文导航”。原文先可靠保存，小批积累后才整理；失败笔记不会删除原文或阻塞后批。这一方向保留。

本轮找到一个可直接解释的接口问题。一份人物材料显示：

```text
Passage 1
Source order 17
原文：吕思博是吕云的家人，关系亲密。
```

工具要求引用本批 `1..16`，模型却输出 `[17]`；同组后续引用也对应历史序号18、19、21、22、32。不是材料太长或时间耗尽，而是**模型同时看见两套看起来都像来源编号的数字**。

精简视图保留本批编号、语义标签、角色、时间和原文，把全局顺序、hash和字符偏移留在程序账本。该输入再次生成时使用了合法的 `[1]` 等本批编号。但仍把“家人”写成“兄弟”：**接口可用性改善了，语义补造没有因此消失。** 其它结果仍有泛化赞美、重复支持组，或标题与实际被讨论人物不一致。

因此，下一步应同时处理两件不同的事：

- 模型引用只显示一套可操作标签；后台保留标签到不可变来源范围的映射，观测中仍能查顺序、偏移和稳定ref。
- 提示以“以后怎样找到这段原文”为目标，允许择要而非把16段硬压进6条摘要；保留未知身份、语气和条件，不把相近人物或话题自动合并。

只改提示，16个输入中13个合法（原条件为5个合法）；说明有帮助，但不应直接上线并宣布导航质量通过。精简视图后的5个也只证明协议局部通过。正确的后续检查应看笔记能否增加不同原文入口，而不是笔记条数越多越好。无依据的导航可能误导召回，但目前最终交付仍回到原文，不应把导航笔记当权威事实。

## 二、Search：模型需要的是阅读任务，不是几百个微小勾选框

长评论输入有550个可选单位，中位长度仅10字符，465个不足100字符。大量独立选项只是页面上的“Upvote”“Reply”“Share”。原因在当前切分：空行阻断合并，抓取页面的每个短按钮文本都变成一个可选择证据。

这不是CL-bench专属规则问题。网页、日志、表格、短列表都可能触发同一问题：**原文保真切分不等于适合模型决策的阅读粒度。** 58884字符的输入虽然未超过总预算，选择任务却已经有550个对象。

保留旧提示、只精简展示后，12个输入均合法，但评论题一次选择549个位置；新提示＋精简视图则选择前100个连续位置。这两种都不能证明有效筛选。无论最终输出是否合法，大量机械选择会把负担推给最后预算裁切和 Answer。

建议把同一来源、同一可读区域内的短段落合成适度大小的连续原文阅读块，保留内部换行、说话人和语境；明确标题和来源边界不能混过。不是删除所有“Reply”或按某个数据集清洗，而是避免每个短界面词都成为独立决策。长期账本仍按精确原文范围保存。过长材料再分页，明确“本次已读”与“尚未展开”。

## 三、Search：补查不是补读，候选截断不是证据不存在

自行车费用案例的头盔120元已被Query召回，但在第33位，没进入24个入口。Select看到链条25和车灯40，最终没有请求有效补查。当前 `read_more` 只沿已见来源补相邻原文，不能直接访问这个未进入入口的候选；用新query再找同一主题，也可能被旧的高排名候选占满。

这里缺的不是“告诉模型应该找头盔”，而是**把召回列表中尚未阅读的材料保留下来，并让后续阅读有可见的增量**。统一设计可分三条路径：

1. 已见片段的指代/条件不完整：读这份来源的相邻正文，复用 `read_more`。
2. 已有未读候选可能补齐问题：继续展开当前候选，不重新搜索同一主题。
3. 当前候选缺少另一侧事实或另一类事件：用描述缺口的query重新查找，不猜答案。

第二条是当前缺失的能力。建议在现有最多两轮内加入候选续接：首轮同时呈现少量未展开候选的语义Reference（标签＋命中片段），继续阅读时新材料进入第二轮的首要位置，首轮已选原文独立保留。最终Select面对“保留的证据＋真正新增的阅读”，而不是再次面对主要相同的前24名。需要验证续接能否增加必要证据，不能只统计补查调用次数。

本轮新提示强调找齐问题后，精简视图的12题全部请求 `read_more`，其中3题还发query；20/100比例题已具备数字，却继续查询泛泛的领导层人口构成。旧提示＋精简视图则12题都未继续。**两端都不理想：提示偏向行动或停止，但没有可靠表达“还有什么没读、这一步能新增什么”。** 本轮增强探索的Select提示不进入默认方法。

## 四、Answer：有帮助，但不能替检索承担缺失事实

| 同一 Search 证据 | 本轮观察 | 判断 |
|---|---|---|
| 2023年说“两年前开始关注健康” | mini＋新叙事仍复述两年前；较强模型新旧叙事都答2021 | 原文已够，存在Answer推算问题 |
| 2022年6月说“上月志愿活动” | mini＋新叙事和较强模型＋新叙事均答2022年5月；较强模型＋旧叙事仍只说上月 | 模型强度不能代替清楚的任务表述 |
| 只有25＋40，没有头盔120 | 较强模型给65的已知小计并说明缺项，仍不能给完整185 | 不确定性表达改善；Search断点未修复 |
| 问Sam，材料实际是Evan；或问John，材料是James | 新默认能指出主体不匹配，区分打算返回与已经返回 | 本地理解更好，不能当召回收益 |
| 项目建议采用的ESLint配置 | 新默认先写“enforced”，后又限定无法证明最终落地 | 仍混淆建议与实施，不能因有免责声明就判对 |
| 冲突题只检出“从未申请”一侧 | 新默认限定当前证据，但无法呈现另一侧主张 | 仍需要Search提供冲突双方 |

复杂扑克、评论引用和人物宣传题仍需逐条rubric/来源审读。更强模型也会混入另一活动、过度限定或错误分类。没有把36个新回答批量交给mini Judge后直接宣布准确率提升。

新 Answer 提示按自然任务表达：完成用户要求；分清谁说了什么、建议还是事实；把说话日期作为相对时间锚点；总量区分不同事件和重复描述；缺证据就限定，而非把部分当全部。实际Search正文逐字保留，只把外层JSON换成“问题／历史证据／记录N”。不传标准答案、隐藏历史或方法内部笔记。

GPT-5.4新叙事36题响应中位9.31秒、最长89.10秒；其中12题mini新叙事中位3.78秒、最长12.42秒，两组题型不完全相同，不能直接当公平速度比。较强模型新叙事输入47,756、输出23,849 tokens，其中推理15,283；输出及推理消耗明显多于短mini回答，实际费用未知，后续以同题成本和结果联合评估。

## 建议流程

```mermaid
flowchart LR
 A["Add：完整原文＋episode索引"] --> W["跨Add积累的小批缓冲"]
 W --> N["LLM整理：择要导航；单一来源标签"]
 N --> Q["Query：BM25＋向量；回到原文"]
 A --> Q
 Q --> R["有语境的原文阅读块＋未读引用目录"]
 R --> S["LLM Select：保留互补证据，判断缺口"]
 S -->|已足够| P["按选择顺序复制原文；记录预算遗漏"]
 S -->|尚有必要缺口| M["续读候选／相邻补读／针对缺口Query"]
 M --> F["一次最终Select：旧证据＋新增材料"]
 F --> P
 P --> B["研究侧强Answer；官方侧独立Answer"]
```

图中单一来源标签、阅读块重组与候选续接是下一轮方案，尚未替换当前Add/Search。不增加无界loop、不恢复关系图、不让Answer读取内部WorkingMemory。先固定输入验证可读性和语义，再用新库完整历史检查检索增量，最后扩大样本。
