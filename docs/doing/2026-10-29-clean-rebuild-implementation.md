# 第三版清洁重构：实施与验证核对

更新：2026-10-30。Git起点60438c3；本轮未提交、未部署。当前实现见[DESIGN](../../DESIGN.md)，计划见[执行计划](../phase-3/2026-10-29-clean-rebuild-plan.md)。

## 结论

已完成旧实现归档和新核心重写。方向是原文证据稳定保存、导航笔记有界生成、Search按问题组合原文。复杂图修改/草案审查/反复修订不再是默认方法的一部分。

这不是“整体方法已稳定”的结论。真实实验显示：写入整理协议有改善，但集合召回、导航语义和遗忘范围仍有质量问题。旧26/75是另一种整理组定义，不能与新批次完成率直接当作同指标比较。

## 已实现

| 部分 | 实际行为 |
|---|---|
| 接收 | 不可变原文、精确episode切段、必要v4向量/词项、缓冲和成功凭据原子提交 |
| 顺序 | 记录角色、原始时间、会话/消息次序及稳定入库序号；入库顺序不冒充事件日期 |
| 整理 | 默认积累两个Add，16段/12000字符或会话边界触发；每Add最多两批，每批一次模型生成最多6条短note |
| 失败 | 必要接收失败无半提交；整理失败记unorganized，不阻断已接收数据，也不反复重试 |
| 导航 | note仅新建，来源链接确定；只读旧笔记供避免重复；精确文本去重，近义合并尚未解决 |
| 检索 | BM25/v4融合→原文披露/来源反链/会话邻接→完整卡片Select→必要缺口补查→独立最终Select |
| 输出 | 只返回已读原文卡，维持Select顺序；不再摘要或按旧检索分数重排 |
| 遗忘 | 直接指令判定→原文页候选→单条独立同主题核对→接收事务内屏蔽来源和派生笔记；仍为整消息粒度 |
| 模型接口 | 唯一tool调用，程序检查字段/编号/数量；没有JSON修补和内部错误重试 |
| 观测 | 实际模型输入输出/token、候选/选择、完整原文范围、装箱遗漏、源代码快照；网页有第三版导航/Select/装箱面板 |

三个开发轮，每轮9次Add、4次Search，分别是LM04、P02、L01、B01，都是切片而非完整历史。

- clean29-evidence：Add9/9，Search1/4，整理3/4。末轮Select仍输出被禁止的queries；Reflection自行产生dialogue类型。
- clean30-evidence：移除节点分类、拆最终Select后，Add9/9，Search3/4，整理4/4；仍有把maxItems当业务字段的错误。
- clean30-final：明确单字段输出形状后，Add9/9、Search4/4、整理4/4。LM04来源2/4；P02来源1/1；L01来源2/2；B01未提供可用自动证据标注。

## 从实际模型视角发现的问题

**协议任务需要更简单。** 原先同一Select既要选择又在最后一轮禁止queries，mini仍重复查询。拆成独立finalize_evidence，仅返回positions后错误减少。其后又观察到模型把schema的maxItems当成业务字段；改为最小形状协议，数量/范围在程序中检查，仍严格拒绝非法编号和多余字段。

**完成整理不意味着检索完整。** LoCoMo 31/31批完成，但集合题“Melanie与家人做过哪些活动”缺少多项；部分候选进入记录的Query列表后未进入Select，部分已出现在Select输入仍未交付。前100字符离线诊断只能定位可见性线索，不能当完整gold证明。24卡容量、两轮查询与集合选择是下一步要检验的约束，不以再增加图节点种类代替证据覆盖研究。

**遗忘必须核对同一事件。** r2把学生退学的反思材料误选为“朋友突然去世”的遗忘目标，也把家庭动漫展误选为电子音乐节。两者都是主题联想而非同一事实。最终r3加入独立候选核对：不传选择器解释，只给删除指令与一条原文；返回布尔值，无审查修订loop。仍需检查同义漏删、整消息连带屏蔽和指令入口漏识别。

**自然叙事优于复杂写入协议，但不是准确性的保证。** note的模型任务显著变小，正文仍可能误归属或重复。它只能影响导航，最终不得作为证据交付；检索必须沿链接回到原文。该限制降低错误传播，但不能保证错误note完全不影响排序。

## 计划核对与后续边界

A归档、B接收、C有界整理、D检索、E观测、H文档已实现；F真实验证已执行并保留失败。G的100题完整质量验收未完成，不能标done。

最终100题冻结清单为benchmark/data/plans/clean30-100-r3/suite.json：6类、26记录、100题、780 Add。该版本只完成1份完整PersonaMem、6题和13 Add，另94题/767 Add未执行；不拼入r1/r2。重新核验官网和正式部署仍未执行。

下一步按实际缺口排序：
1. 遗忘粒度：从整条消息屏蔽改成只影响已确认主题的可检索范围，保证无关原文仍有入口；先验证误删/漏删控制。
2. 集合召回：围绕多活动、跨时间比较类问题评估候选分组与补查覆盖，查清证据丢失位置，再决定是否扩大24卡/两轮。
3. 导航增益：对同一完整历史单独量化note带来了哪些本来找不到的来源，以及重复与错误归属的代价；不因有note就宣称图推理有效。

默认方法只有当前实现，以上未实施设计没有隐藏分支。当前可继续做有观测的研究，但不宣布正式参赛就绪。
