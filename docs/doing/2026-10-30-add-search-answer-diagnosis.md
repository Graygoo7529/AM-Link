# Add → Search → Answer：失败归因与模型对照

2026-10-30。只读复核当前源码与reading30-public-r2保存结果；本轮没有修改方法、切换模型或发起模型调用。官网赛事页确认参赛方只提供Add/Search，Answer/Eval由平台统一完成；用户文档本轮抓取失败，未确认官方具体Answer型号，不能把本地mini称作官方复现。

## 三层责任

Add应保存原文、主体、语气和时间依据，按必要遗忘边界建立索引；Reflection只产生能带回原文的导航。Search应交付足以支持问题的证据组合，且保留限定语和归属。Answer应在证据范围内完成推断、计算、拒答和任务执行。最终错误不自动代表同一个环节失败。

| 环节 | 本轮已确认 | 仍不能推出 |
|---|---|---|
| Add接收 | 400/400成功；活动来源都有episode | 所有历史的同义遗忘正确、原文语义已经组织好 |
| Reflection | 409/420批完成；旧note背景可见 | 笔记具有足够区分度，或对召回有净收益 |
| Query→披露 | 自行车头盔120在Query第33位，24入口截掉 | Query召回就等于Select实际读到 |
| Select→继续搜索 | 两次非法位置0；公开r2额外Query为0、仅1个补读位置 | 已有两轮能力就具备有效多跳／集合补全 |
| 装箱 | 本轮36次装箱均未因最终预算丢所选单位 | 已选单位包含所有必要事实或完整限定语 |
| Answer | 多题已交付时间锚点仍不归一化；任务分类和执行也有错误 | 所有未达标都是记忆不足，或换强模型必然解决 |
| Eval | 原文“邻居”和参考“熟人”等有判断冲突 | mini分数就是准确的最终质量测量 |

## 三个可核对的断点

1. **自行车费用**：原文含25、40、120。最终Search给出25、40，以及头盔购买但无金额的材料；120已召回却未披露。Select本可发现“有头盔但价格未知”并补查，却输出空queries。Answer将已见65宣布为总额。缺口包含披露／补查，也包含Answer未表达范围不足。更强Answer最多识别缺口，不能凭空证明185。
2. **志愿活动时间**：`read30-public-r2-10-locomo / qa-28`交付的同一张Evidence 2同时有2022-06-19说话时间与“last month”。理论答案为2022年5月，不应推精确日。mini却声称无法知道月份。`09-locomo / qa-25`同样交付2023年与两年经历，却只答“两年前”。这里已有证据，主要应检验Answer提示／能力及时间元信息的可用性。
3. **ESLint已执行规则**：`06-beam / abstention:0`返回用户仍在求助配置、助手给出的配置和解释；mini把它们写成用户已执行规则。角色可见不等于实际采用状态得到证明。Search的上下文完整性和Answer的认识边界需分别检查，不能一概过滤assistant材料，也不应把示例升级成个人事实。

当前本地Answer提示为`amlink-answer-diagnostic-v2`，mini，4096输出上限（批量运行），完整读取保存的Search.content，无二次截断。提示允许普通推理，同时禁止补造缺失日期；来源头只强调说话时间不是事件时间，没有正面说明它可作为相对时间锚点。这是可检验的表述歧义，不能未做对照就断言是全部时间错误原因。来源相对时间归一化和常识桥接也要区分，后者依任务契约决定是否允许。

## 是否使用更强Answer

建议增加**研究侧的固定证据对照**，先不把分数增长当作记忆方法改进。不改正式Add/Search的mini/v4模型限制，不在Search里预先生成最终答案。

| 研究输入 | mini Answer | 更强推理型Answer |
|---|---|---|
| 冻结的实际Search结果 | 当前端到端基线 | 同一证据可被更强读者使用的程度 |
| 人工核对的必要原文组合 | 充分证据下mini的表现 | 进一步检查题目／标注／任务本身的难度 |

必要原文组合属于离线诊断，不给模型标准答案，不改Add/Search，也不计正式检索成绩。两模型同时失败不证明缺证据；必须结合原文审查。强模型答对还要查依据，防止常识猜中或公开数据记忆造成虚假检索成功。

实施对照时冻结来源、顺序、问题和同一可见提示；单独保存答案身份，不覆盖mini原结果。先用36份成功Search的现成内容，无需重跑400 Add；两次Search失败保留为独立失败。另选择少量正反例做必要原文控制，并用重复调用估计波动。提示澄清应作为另一变量单独比较，不与换模型同时归因。

评分也不宜只依赖mini：使用更强独立评阅与人工抽检，保留逐项rubric和争议，不让同型号Answer与Judge的共同盲点决定方法走向。代理是否支持目标强模型、API参数和实际型号必须另行验证；本轮没有探测可用性。
