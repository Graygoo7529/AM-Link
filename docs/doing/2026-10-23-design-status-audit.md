## 新复现：模型选择的引用与实际执行对象错位

### Search 的裁剪前后位置不一致

`Engine._next_bfs_action` 按完整 `context.frontier` 生成工具位置及解码；模型拿到的却是 `_model_context` 裁剪后的 frontier。

本轮合成反例通过真实的语境投影、工具定义和动作解码路径得到：

```text
程序完整候选：[A, B, C]
模型实际看见：[C]                 ← 预算仅容纳最近读取的 C
模型返回：Inspect(position=0)
程序实际执行：Inspect(A)          ← 错用完整列表解码
```

这会直接干扰对 BFS 的归因：看似“模型没有选到正确证据”，实际可能是程序读错对象。

### Reflection 即使不裁剪也有位置歧义

内部 References 的插入顺序为 `[Zulu, Alice]`，但实际模型请求使用按键排序的 JSON 序列化，正文变成 `[Alice, Zulu]`。工具只要求 `reference_position`，没有给每条引用显式绑定位置；返回0仍按内部顺序解释成 Zulu。Inspect、Backlink、Evict 都使用这套映射。

**建议优先修复，属于落实已有协议，不增加方法概念：**

1. 先完成当前调用的语境预算投影，再生成有序的可见引用清单。
2. 每条显式给出位置、语义 ref 和叙事；参数枚举、模型输入、结果解码共用同一份清单。
3. 不按字典键顺序推断位置，不允许工具选择本次不可见引用；没有可选项时只提供可执行动作。
4. 观测保存该清单、模型选择位置和解析后的 ref，验证三者一致。Select 已有显式位置约定，应统一实现这一工程规则。

## Reference 的来源覆盖仍不等于模型证据覆盖

`complementary_passages` 用 `source_ref` 去重，实际限制为同一来源只能有一个片段。合成的一条3851字符消息同时包含开头的活动日期和末尾的票价；查询分支分别命中两者、预算1600字符，最后仍只展示开头380字符。它证明了同源多处命中缺口，不代表真实模型的失败率。

另外，Reference 已带范围的片段进入 `_model_context` 后会再次截短。当前 `model_projection` 只记录片段文字截短前后的长度与完整性，没有把二次裁剪换算回原文范围。Item正文和来源预览也使用独立截取。因而“账本记录来源存在”“执行过 Inspect”“模型看见关键原句”仍是三个不同事实。

**建议：**按同一原文中的多个不重叠范围选择片段，合并重叠窗口；每次裁剪都保留最终原文坐标。Select、Inspect、BFS、最终装箱沿用同一来源与范围映射，不重新随意换成另一处片段。对长节点，允许后续 Inspect 定位未展示部分是待设计的内部参数扩展；应配合已读范围去重，不能继续仅以 `(ref, inspect)` 禁止所有进一步披露。

不要求把全部原文塞进每次调用，也不让模型制造“缺失证据”。目标是能准确回答：**本次到底展示了哪几句，下一步还有哪些部分可以读取。**

## 图发现成功，最终仍可能没有输出

当前 `_search` 的最终 pool 按“Query 候选在前、图新增候选追加在后”排列；`_assemble` 按此顺序装入 `top_k`。修复“旧检索分数覆盖 Select 排序”后，这个顺序得以保留，但它也意味着 BFS 新发现的重要证据没有统一竞争输出位置。

本轮合成反例沿真实 Search 图遍历和装箱运行，发现：

```text
Query：A（Ada使用哪份指南）、B（档案馆门的颜色）
Inspect A → 发现 C（指南指定的地点是 Florence）
top_k=2 → 最终仍返回 A、B；C正文与 Florence 均未输出
```

这是固定候选与确定性图动作的控制实验，不是一次真实 LLM 表现。它说明增加图跳数本身不能解决最终证据缺失。

执行计划自检时再次复跑该反例，图夹具使用允许的 `fact → about → entity` 关系；C仍被实际图遍历发现，而地点正文没有进入输出。其余引用错位与同源片段反例也仍可复现。

**建议保留已确认路线：**默认先完善确定性证据组合，再离线比较受限 LLM 装箱。

- 确定性方案需要在整个候选池分配预算，利用已探索路径和来源差异组成证据组；保留必要的主体、关系及其依据，避免无关卡片先占满。上游 Select 的相对顺序可作为偏好，不能成为图新增证据永远靠后的硬规定。
- 关系的 `source_refs` 也应进入相关证据组；不能仅有关系两端标签却没有支持关系的原句。
- 受限 LLM 对照只选择已有片段编号、顺序和必要组合，系统确定性展开并校验范围、去重与预算。它仍不是 Answer，不改变默认路径。
- `closure=complete` 继续只表示节点声明来源完整；题目所需证据是否找齐必须另看可选标注或人工复核，不能混为一项指标。

## Reflection：从“调用过工具”走向“读过相关证据”

上一轮修复已要求已有变更目标逐一出现在声明与实际探索记录中，但仍有三层缺口：

1. **选择正确**：先修复引用位置映射，否则风险门槛审计的是错误对象。
2. **可见充分**：探索记录只标识操作发生，不证明目标正文或相关来源进入了后续模型输入；Backlink 读到邻居也不等于读完目标本身。
3. **语义相关**：全新人物/关系没有已有目标时，任意探索记录仍不能证明做过相关旧身份查找。`no_prior_match` 没有确定性的“检索空间穷尽”保证，应保留为模型声明。

建议按变更风险检查所需材料：更新旧节点需可见旧正文与新来源；冲突需两侧原句和适用条件；人物复用需身份线索；关系需端点及支持关系的来源。程序验证材料与可见范围，模型判断含义，人工或切片检验语义质量。不要把程序门槛包装成“已证明正确”。

还需要协调探索门槛与工具预算：默认8轮且每次仅一个引用；若有8个必须探索的旧端点，仅8次读取加最终Mutation就需要至少9轮，尚未计Query或被门槛拒绝的一轮。保留单ref工具时，应显式计算所需读操作与提交预算；超过上限时有明确的拆分/未完成结果。是否扩展为一次读取多个ref仍是设计选项，不能靠增加内部重试解决。

## 缓冲、协调器和 Query 仍需设计收敛

### 缓冲不是延长一次 Add 的等待

当前默认8条消息/6000字符触发；`now/never` 等普通词也被当成硬更新信号。本轮确认 “I enjoy hiking now.” 和 “I have never visited Paris.” 都命中该规则。会话切换触发后，批次只按条数/字符切分，没有优先在上一会话末尾收束。

建议先修普通叙事误触发，再实验会话前缀的整理范围：旧会话完整前缀优先整理，新会话首条已由最低episode保证可检索，其高层整理可以继续积累。具体目标水位应在触发时确定；已承诺处理的目标不得后退，硬更新/遗忘仍须按顺序完成必要前缀。这是待确认的触发策略调整，不是当前实现。

当前 `reflection_stop` 是“本批确无额外Mutation”的终结，会推进水位；它不是“材料还不足，留待下一次”的暂停。不要混用这两个含义。若要增加 Mutation 前跨批维护阶段，应在目标设计中明确保护尚未完成的WorkingMemory、水位和恢复边界。

Workspace 虽然保存，持久内容没有自动容量回收；当前主要裁剪送模型的副本。后续应让 Evict 与确定性预算维护作用于活跃Workspace，并保护未完成变更所需材料，避免长期保留越来越多但模型始终看不到的节点。

### 协调器仍是计划，不是已经完成

当前同用户整段Add先拿锁，再追加原文；尚无并发先追加、极短合并窗口与单协调器。排队已计入1740秒期限，能保护顺序，却不能体现并发合并的价值。应在证据协议稳定后单独验收并发追加、逐请求目标水位、失败重放、退出恢复和排队期限，不把它混入一次语义质量实验。

### 类型倾向 Query 尚未落实

当前查询扩展输出多个字符串，合并后统一 Select；没有按 `episode/person/entity/concept/event/fact` 的语义倾向。Reflection 的 `reflection_search` 仍只执行 Query/Select，后续图操作在 Reflection loop 中继续，命名与完整 Search 抽象有差异。

建议不重开 raw lexical 通道，不先指定六类固定比例。先在同一问题上对照“无类型提示”与“分支携带可选类型倾向”，保留原问题广泛查询、分支先合并再Select。先测不同类型在哪一步消失，再决定是否需要预算保护。内部 `seed_count` 实际只控制Select触发阈值，应在实现时改成与语义一致的名称并兼顾配置迁移。
