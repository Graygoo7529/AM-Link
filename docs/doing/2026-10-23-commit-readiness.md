## 临时文件为什么出现在根目录

此前测试命令显式使用了 `--basetemp .tmp-phase2-20261015i` 等根目录路径。Store 会在 SQLite 文件旁保留一个 `.sqlite3.owner` 锁文件；关闭 Store 释放锁，但不删除锁路径。原 ignore 覆盖了数据库及 `-wal/-shm`，没有覆盖 `.owner`，所以数据库被忽略，锁文件出现在未跟踪列表。

本轮处理：

- `pytest.ini` 默认收集当前方法、靶场、数据层和可视化测试，缓存放在 `amlink/data/pytest-cache/`。
- 根 `conftest.py` 为每次测试分配 `amlink/data/pytest-tmp/run-<唯一编号>/`，自动创建父目录，支持并行独立运行。显式 `--basetemp` 仍优先；标准库 `TemporaryDirectory` 继续使用系统临时目录。
- `.gitignore` 增加 `.db.owner/.sqlite.owner/.sqlite3.owner`、根 `.tmp-phase2-*/` 和 `/pytest-tmp/`；未使用通配所有 `.tmp*` 的规则隐藏其他可能的工作文件。
- 锁文件保持运行时原有语义，不通过修改 Store 删除锁文件来解决 Git 问题。旧临时目录不必搬动或强制删除就能排除在提交之外。

已核对历史 Git 记录：`pytest-tmp/` 内4个一字节 owner文件和4个 pytest `current` 符号链接已被跟踪。它们不是源码或一期/二期归档。当前 status 的 `D` 混有文件系统权限不可读，不能据此认定它们已被物理删除。ignore 不会取消已跟踪文件；准备提交时执行：

```powershell
git -c safe.directory=B:/WorkSpace/AM-Link rm -r --cached -- pytest-tmp
```

这只取消当前版本的跟踪，不删除工作区文件，也不清理历史提交。不要用 `git clean -fdx`，研究数据库和私有配置同样位于忽略路径。

## 下一阶段方法研究

本轮修复了可确定复现的边界，仍存在以下方法问题：

- **范围要能定位**：Reference不同来源可互补，但同一长消息每次投影最多一处；二次模型裁剪尚未完整映射回原文坐标。
- **读过不等于理解正确**：门槛能核对已有目标是否探索，不能自动证明新人物归属、关系语义或“没有旧匹配”的判断正确。
- **来源闭合不等于答案闭合**：complete 只说明节点声明来源已展示；遗漏了应召回的另一个节点，仍可能无法回答。最终 Query 与图新增候选的统一证据组合、受限 LLM 装箱对照仍待实施。
- **缓冲仍需全局视角**：持续Workspace与跨批探索应与完整会话、整理触发共同校准，不默认每次Add都做Mutation。

设计与顺序同步在[改进计划](../phase-2/method-improvement-plan.md)。真实调用当前只定位到本机网络权限阻断，不能把未获HTTP响应当作供应商故障；后续联网复验采用原有小切片优先路线。
