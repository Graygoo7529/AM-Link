# AM-Link Answer 靶场与真实案例复核

日期：2026-10-08。用途：给现有 Add/Search 靶场补上独立诊断 Answer，检查 Search 返回的实际上下文能否支持正确回答，并用跨数据集样本复核 Add/Search 的真实失败点。

## 执行范围

`python -m benchmark answer` 只读取已保存 Search trace 中的问题和真实返回内容，不读取 task annotation、标准答案、证据标签或评分计划作为模型输入。Answer 使用 `gpt-5.6-luna` 与固定提示 `amlink-answer-diagnostic-v1`；每题单次请求、不重试，45 秒超时，最多生成 700 个 token。运行记录保存模型输入/输出、usage、耗时和错误阶段，并以 `answer`、`model` span 接回同一 Search；人工核对在模型调用之后，以 `eval` span 记录。

新跑了 7 个 AM-Link 样本切片，另对既有运行执行 Answer。7 个新运行使用现有 per-run 上限：24 次 provider call、325,000 输入字符。新切片共 25 个 Add 请求，其中 7 个成功；Search 成功 3/7。共捕获 13 次 `gpt-4o-mini` 调用（32,500 输入 / 4,569 输出 token）和 15 次 `embedding-3` 调用（2,574 输入 token）。费用未从 provider 获得，保持未知。

8 次 `gpt-5.6-luna` Answer 调用成功，合计 6,968 输入 / 880 输出 token。7 个是本次目标案例，另 1 个是后院活动建议的未评分探索样本；该样本不作为遗忘测试。LM04 首次本地受限网络调用产生 `URLError`，随后在已授权网络环境下单独重跑成功；不是靶场内部重试。

## Add/Search 阻断

| 案例 | 运行切片 | 实测结果 | 断点 |
| --- | --- | --- | --- |
| LoCoMo L01 跨会话关联 | 2 / 419 个历史单元 | Add 1/2；Search 因 `user_add_incomplete` 失败 | 第二个 reflection 输出在严格 mutation 校验时带有 schema 外字段 `purpose: "reflection"`，返回 `mutation_schema_invalid`。两个锚点不能形成可检索的跨会话路径 |
| LongMemEval LM01 新纪录更新 | 2 / 413 个历史单元 | Add 1/2；Search 被 incomplete 状态阻断 | reflection 把一个 fact 连到 episode，并使用不允许的 `about` 关系，返回 `mutation_relation_types`。新样本中的 25:50 未进入可用记忆；旧的 27:12 不足以回答当前题 |
| PerLTQA P02 中文叙事 | 2 / 71 个历史单元 | Add 0/2；第二次 Add 是 `prior_add_incomplete`；Search 被阻断 | reflection 用 `about` 把 episode 连到 person，违反允许的节点类型组合。当前样本的模型输出语言正确，但图边协议没有通过校验 |
| PersonaMem-v2 PV04 明确遗忘 | 全部 241 个历史单元 | Add 1/15；一次 `mutation_schema_invalid`，后续 13 次 Add 为 `prior_add_incomplete`；Search 失败 | 尚未进入 Answer，不能据此评价是否遗忘或旧偏好是否回流 |

这些轨迹说明失败主要发生在 Add 的 reflection 输出到图变更校验之间，而不是 embedding 或 Answer。方法当前把一次 mutation 的无效结构作为 Add 失败返回，并阻止同用户后续 Add/Search；这避免了“半成功”的假象，但也让一个额外字段或一条非法边可以截断整个用户请求链。下一步应针对输出契约做 schema 约束和错误路径观测；不要用内部模型重试掩盖失败，也不要在没有显式记录的情况下悄悄丢边或报告成功。

## 设计结论

完整来源覆盖是 Answer 正确回答的必要条件之一，但不充分。LM04 与 LM05 说明 Search 给到明确、完整证据时，较强的下游模型能正确去重与计算；L04 说明 Answer 仍需检查问题中的多个实体/答案槽位，并逐一核对证据；LM02 说明时间、日期和计数口径要保留并显式解释；B02 说明冲突时不能先给肯定结论再附加保留语；M01 则说明输出可见矛盾比编出唯一事实更安全。

面向 Answer 的设计补足点：

- 对复合问题先列出所有必答槽位，逐项查找 Search 结果中的支持证据，再组织回答；避免 L04 只答出一半。
- 事件类问题保留发生时间、重复提及来源和事件身份；LM04 用事件去重后再聚合金额。
- 时间问题同时保留原始日期/时间戳；当数据集参考采用日期差而 trace 支持精确时长时，回答两种口径并说明采用值，避免 LM02 的表面不一致。
- 冲突事实先陈述“当前记忆有两种说法”，再询问用户核实；不要把排名第一的冲突状态写成确定答案。
- 对人物/关系链逐跳检查主语、关系和宾语是否有来源支持；来源互相矛盾或缺少一跳时明确降级为证据不足。
- Answer 的人工核对必须与 Add/Search 召回指标分开。Search 命中不能直接算回答正确，Answer 正确也不能证明记忆结构具备稳定泛化。
