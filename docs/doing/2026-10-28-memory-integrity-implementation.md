## 交付内容

### 1. 已记录的情景不再被换题，来源对应当前陈述

以前同一派生 episode 可从“链条 $25＋车灯 $40”变成“头盔 $120”，旧修车来源还会自动并回。现在全部既有 episode/fact/event 的正文及时间不可改；最低 episode 的来源也保持原约束。Reflection 不再新建摘要 episode，Add 的保真原文投影继续承担情景日志，新信息用 fact/event 表示。相同正文可以补支持，不能借补支持替换陈述。

person/entity/concept 内容变化后，只提交此次审查认可的来源；正文/时间完全相同时才延续旧支持。历史引用留在原文和提交轨迹里，不自动冒充新正文的依据。规则同时进入草案预检与审查后提交，审查模型也无法绕过。

最终 LM04 R6 已存修车事实仍保留两项金额，未被头盔覆盖；头盔原文仍由最低 episode 检索到。但头盔增强组未完成，所以不能说它已经生成了理想的新事件节点。同义复述的去重质量也未获得整体证明。

### 2. 审查交付最终正文，程序判断保留或修订

同组联合审查保留，顶层为固定 `uN` 键，移除 `reviews` 包装和每项重复的动作 anyOf。节点最终只填正文、时间、来源位置、理由；`text=null` 表示撤销。程序比较前后正文和时间，生成原有 keep/revise/drop 观测记录。关系仍用 keep/drop，只有 supersedes 需要替代原句，节点不再填写关系专属字段。

五轮组件对照表明，额外要求模型判断“保留还是修订”，容易让它只判真假并删除可修正信息。最终以“写出忠于原文的陈述”为任务，先给原文，草案旁再显示直接引用。原文重复展示仍计入统一预算，并沿用现有分页；不是隐藏增加窗口。

同一冻结输入、同一序列化方式比较：完整工具定义从 **4487 降到 2749 字符（约 39%）**，整个输入从 **11655 降到 11216（约 4%）**。这只是结构负担减少，不能声称模型成本下降 39%，也不能证明协议已稳定。

### 语气与时间放在同一审查，不增加新模型步骤

最终组件正反例有实际修订：

| 原文与有问题的草案 | 最终组件 R5 的结果 |
|---|---|
| might go back → plans to return | 改为 might go back，保留可能性 |
| 已明确决定、一定返回 | 保留承诺，没有统一弱化 |
| 教练建议、小林尚未决定 → 小林决定游泳 | 改为教练建议且小林未决定 |
| 小陈已决定游泳 | 保留明确决定 |
| recently → 某个精确日期 | 保留 recently，标准化日期清空 |
| April 20th → April 20, 2023 | 保留 April 20th，不补年份 |
| 原文明示 April 20, 2023 | 保留 2023-04-20 |
| yesterday，无锚点 → 精确日期 | 保留 yesterday，日期清空 |

程序检查 time_expression 是否确实出现在所选可见原句中。实测仍发现模型拿消息日期补年，故补入必要条件：标准化日期年份必须出现在所选原文，元数据及 ref 名称不算；原文及来源时间仍保留。引用存在、年份存在都不是完整语义证明，也不能验证任意日期推断。

真实 R5 的错误反馈还暴露：模型把 `time_expression` 原样放回 patch，只改了“修复理由”。最终反馈逐项显示草案 ref 和时间字段，并明确要求清空错误表达及依赖日期，或逐字引用原文。R6 真实 patch 已执行清空；它是有内容的局部修订，不是重试相同模型调用。

## 剩余问题与下一步依据

1. **关系误判仍会拖住有效的新事实。** 最终 LM04 误把补充消费当 supersedes，原句守卫有效但整理未完成。需要针对“节点可成立、关系不成立”的真实草案研究如何完成局部修订，而不是放宽替代依据或机械增加模型轮数。
2. **浅协议不等于稳定交付。** drop 与来源字段的含义仍容易混淆；可以进一步研究把“用于解释撤销的原文”和“提交陈述的支持”区分清楚，但本轮没有猜测修复错误输出，也没有按失败自动换协议。
3. **新增节点仍可能过于概括、重复或带推断。** 中间 LM04 轮次出现“主动安全意识”“定期维护习惯”等过强概括，P02 仍复制较长原文为 event。保真保护解决覆盖，不自动解决增量价值。应继续以具体新增断言为单位核查成本与收益。
4. **Select 与 BFS 不能由本轮推断已改善。** LM04 重复来源覆盖在 2/4—4/4 波动；最终零边、L01 BFS 有截断。没有为了本轮指标调整候选比例、强制生边或追加装箱模型。
