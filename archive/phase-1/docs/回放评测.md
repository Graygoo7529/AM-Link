# Add/Search 回放评测

回放工具读取 JSON manifest，按原协议向一个正在运行的 Add/Search 服务发送请求，并输出质量、延迟和错误指标。它既可以测试本机 Uvicorn，也可以测试公网候选 API。

## Manifest 格式

顶层结构：

```json
{
  "version": 1,
  "cases": [
    {
      "id": "case-id",
      "adds": [],
      "searches": []
    }
  ]
}
```

`adds` 中每项是完整 Add 请求。`searches` 中每项包含：

- `id`：查询用例 ID；
- `request`：完整 Search 请求；
- `expected`：一个或多个期望证据目标；
- `expect_empty`：仅用于应该返回空结果的查询，不能与 `expected` 同时设置；
- `category`：`general`、`single_hop`、`temporal`、`multi_hop`、`open_domain`、`adversarial` 或 `historical`。

期望证据目标支持稳定 ID 或内容片段：

```json
{
  "ids": ["mem_xxx"],
  "contains_any": ["expected evidence fragment"]
}
```

同一个 multi-hop 查询应把关系链中的每条必要证据写成独立 target。示例见 [replay-smoke.json](../examples/replay-smoke.json)。

## 运行命令

无鉴权本地服务：

```powershell
.\.venv\Scripts\python.exe -m aml_memory.replay `
  examples\replay-smoke.json `
  --base-url http://127.0.0.1:8080 `
  --db-path data\aml_memory.db `
  --output data\replay-report.json
```

Bearer 鉴权服务：

```powershell
$env:AML_API_KEY = "set-in-secret-manager"
.\.venv\Scripts\python.exe -m aml_memory.replay `
  examples\replay-smoke.json `
  --base-url https://memory.example.com `
  --auth-scheme bearer
```

密钥只从 `--api-key-env` 指定的环境变量读取，不写入报告。async enrichment 可通过 `--settle-seconds` 给 worker 留出处理时间。
真实 provider 的小规模回放可用 `--add-interval-seconds 2` 控制相邻 Add 的间隔；该参数只影响本地回放节奏，不改变 Add/Search 协议。

## 输出指标

- Add/Search success rate、p50、p95、max latency；
- `evidence_recall@1/5/10`；
- `hit_rate@1/5/10`；
- MRR；
- 空结果准确率；
- evidence group 重复率；
- temporal/historical recall@10；
- single-hop/multi-hop/open-domain/adversarial recall@10；
- multi-hop chain coverage@10；
- 应用内回放时的模型和 embedding 调用计数；
- 查询级 target rank、结果数和错误类型。

使用 `--db-path` 时，重复率按数据库中的 `evidence_group_id` 计算；测试远程 API 且无法读取其数据库时，退化为规范化 content 重复检测。
