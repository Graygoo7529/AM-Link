# Add/Search 交付边界、局部整理与证据连续性实施核对

2026-10-27。基线 `ee6fe76`；执行[用户确认的计划](../phase-2/2026-10-27-add-search-contract-and-convergence-plan.md)。本轮代码直接成为默认方法，没有另设关闭开关、后台补偿或模型重试。未部署、未提交。当前图见根 [DESIGN](../../DESIGN.md)。

**结论：接口边界与进度恢复的工程改造完成；真实整理稳定性、关系语义与完整证据集合尚未验收。** 224 项回归、3 个子测试通过。真实实验全部从新库开始，共 6 个靶场档案、41 次 Add、21 次 Search，覆盖 5 类数据；包含重复问题和复验，不能当作独立测试集。仅两份不同的完整历史，其余是诊断切片，不满足计划的 6 份完整历史要求。

## 1. 已交付的行为

### Add：先可靠接收，再尽量整理

原文、WorkingMemory、保真 episode、BM25、向量和成功凭据一次短事务生效。必要模型准备在事务外；准备、索引或凭据写入失败，整次接收不留下新记忆。提交后，即使响应丢失，同 ID/同 payload 再来直接读取成功凭据，不再调用模型。

接收后仍在本次请求内利用剩余时间整理，默认总期限 1740 秒，包含同用户排队；留出最多 5 秒完成记录和返回。Reflection 未完成或失败不撤销已接受材料，也不将该组标为完成。后续新 Add 可带来增量；成功请求重放不能再次驱动整理。没有后台 worker。

明确遗忘是接收的必要部分：先识别真实用户指令并定位来源，再与本次接收原子屏蔽。引用中的“忘记”不等于用户授权；定位模型失败则本次 Add 失败，旧材料不变。当前遗忘粒度仍是整条 raw 消息及依赖节点，不声称能细到同一条消息的单个属性。

### Reflection：局部失败不阻断整批

- 原文段通过必填 `pN` 项分配自然问题，完全相同的问题由程序聚合；不再交叉维护动态组号。人物资料应按相关资料组织，不按字段机械拆组。
- 冻结计划 v3 保存逐组完成凭据和未完成草案。后组可以完成，连续水位只越过真正全部完成的前缀；不以跳过失败组伪造水位。
- 恢复草案先核对来源与旧节点版本。无相关增量且失败输入未变则跳过，不重复同样的模型工作；旧草案不能覆盖后来修改的节点。
- 联合审查按已知对象 `uN` 返回修改/保留/撤回及具体剩余事项。合法修改先保留在草案，然后补读或 patch；未解决时不提交。重复键、遗漏项、错误动作整次拒绝，不猜测修复。
- 去重同源重叠原文，保留真实支持；保留 `supersedes` 必须给出可核对的替换原句。`about` 不表示泛泛相关；`contradicts` 先核对同一主体、属性、事件及条件。

### Search：必要检索严格，后续扩展逐步交付

初次 Query、embedding 和必要 Select 失败仍返回错误。正常空候选或合法选择为空才返回空结果。BFS 每步在临时语境中完成；后续局部模型、协议或预算失败可以丢弃本步，返回之前已完成的证据，同时记录错误和停止原因。存储损坏、跨用户/缺失来源、错误原文版本或片段内容不能这样处理，仍明确失败。

Select 共用 80000 字符上限，按预算而非每 ref 固定 4 段提供互补材料；所选范围贯穿语境和装箱，预算遗漏有账本。装箱保持顺序，重复原文 episode 不挤占另一张证据卡；路径端点/来源未闭合时不展示关系成立，只保留合法的独立材料。没有新增 LLM 装箱或 Answer。

数据库版本为 **3**，冻结计划为 **v3**；旧库明确拒绝，无静默迁移。历史实验保留只读研究，新运行不复用旧库。Workspace 阅读格式仍 v2。

## 2. 确定性验证

根回归 **224 passed、3 subtests passed**。新交付边界测试 25 个参数化用例，另有网页交付状态测试。覆盖：

- embedding、索引、成功凭据写入失败回滚，保留此前及其他用户材料；响应丢失后重开库幂等返回。
- 同用户 4 路同请求重放仅一次必要 embedding；相同 ID 不同 payload 明确冲突；HTTP/native 语义一致。
- 已接收但未完成的整理返回成功；一个失败组不阻塞另一个组；无增量不重做；合法修订续做、过时草案不恢复。
- 必要 Query 失败、存储错误不能变成空结果；局部失败不泄露临时引用/路径；Select 合并预算同样适用。
- 7 份独立原文持续进入 Select、语境和装箱；缺失、过时、跨用户来源显式拒绝；重复 episode 不抢占另一证据卡。
- 网页可同时显示 API 成功、内部错误、整理未完成及 Search 局部终止；旧记录缺项仍为未知。

唯一测试提示来自已安装 Starlette 的 httpx TestClient 弃用提示，未修改依赖配置。

## 4. 真实效果与未关闭问题

### 人物资料：分组收敛有效，但类型修复仍会卡住

同一人物的计划从 25 组降到 5 组，GPT 从 202 次降到 50 次；6 问来源覆盖从 5/6 到 6/6。冻结首批资料的单次分组也从逐字段 12 组变成 1 组。这支持“相关资料一起处理”的方向，不能证明所有人物都会如此。

最终仍有一组无进展：模型把职业/爱好/国籍等写成多个 event，又提出 person → event 的错误 `about`。明确反馈后仍未修好。该组没有提交，但其它组正常完成，episode 支持 Search；这是交付边界有效、整理质量仍未通过的具体例子。已提交的 `contains` 和宽泛 person 正文也有语义问题，不能因为边数减少就认定图更好。

### 棋局：先确定同一事件，再判关系

R2 产出 27 event、7 about；审读发现把同一人参与的不同比赛相互连接，类型合法但关系不成立。未完成组同时暴露引用撞名、审查格式不符和无进展；现在可以保存草案，并推进其它组。

冻结真实双端点与原句后，补充自然叙事使 3 条错误 about 被撤回。但另一份 14 对象审查仍认为“同日赢甲、输乙”相互矛盾。进一步明确同一对手/同一事件/条件后，该份的 7 条错误 contradicts 全部撤回（部分由端点改写后的程序检查撤回）。这仅是一次冻结输入复验，未证明完整棋局重建的关系质量。正向人工对照保留了明确的配额更新 supersedes，补充兴趣对照撤回错误 supersedes，避免把“所有边都删掉”当目标。

### LM04：三个独立金额齐全，与四份来源齐全是不同指标

最终 R6 为 **2/4 来源覆盖**，不能引用较早 R1 的 3/4 替代。实际返回包含 $25 链条、$40 车灯和 $120 头盔三项原句。另两条 $40 车灯复述已完整展示给 Select，却被 Select 去掉；不是 Query 漏召回、片段截断或最终装箱丢掉独立金额。

Select 选择了维修 event、同源 episode、头盔 episode。装箱将前两张重复原文合并为一张，最终两卡。不能机械地把两次复述再算两笔消费，也不能仅凭金额齐就宣布回答正确；本轮没有 Answer。仍需事件同一性与“新证据贡献”评估。最终 Reflection 还有 `reflection_review_incomplete`：严格工具定义不能保证供应方总返回符合结构的结果，当前明确保留未完成，未加内部重试。

### 多跳与局部失败

R3 Reflection 真实执行 4 次 Backlink，R4 Search 执行 1 次 Backlink；路径工具已经接通，但次数不代表多跳有效。R4 的 LoCoMo 多跳问题只覆盖 3/7 标注来源，仍未验收。

R3 一次 Search 在模型工具输出失败后返回已有材料；R4 两个 BEAM 问题分别在工具输出无效和 BFS 参数无效后局部终止。三次均保留子错误、丢弃失败步骤，返回已完成语境。BEAM 任务没有可用的字面来源评分，不报覆盖率，也没有运行 Answer。故障测试进一步核对半成品引用不会混入结果。
