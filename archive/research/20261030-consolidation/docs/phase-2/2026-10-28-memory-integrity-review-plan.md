# 节点保真与简明来源审查执行计划

2026-10-28，基线 `ff706cb`。用户已确认两个核心方向，并要求把语气、时间检查一并实施。依据：[实际断点复核](../doing/2026-10-28-practical-improvement-audit.md)。已实施并逐项核对，见[实施报告](../doing/2026-10-28-memory-integrity-implementation.md)；工程通过、组件实测和整体质量分别报告。

## 一、保持节点语义与当前支持一致

已存 episode 是一段已经发生的情景记录，不能在同一 ref 下换题或改变日期；保护范围由最低 episode 扩至全部 episode。fact/event 继续正文与时间不可改，同一陈述可以补充来源。新信息写 fact/event；Add 已提供保真 episode，Reflection 不再生成同义摘要 episode。已有 episode 仍可被引用、Inspect 和建立 contains 关系。

person/entity/concept 是可更新的导航节点。正文或时间变化时，只提交这次审查认可的支持来源，不能自动并回历史引用。正文与时间完全不变时，已有支持仍可保留，并增加新支持。历史提交和审查轨迹保留，不引入额外版本系统；原文、最低 episode 和成功接收凭据不受影响。

预检和最终写入采用相同规则；模型拿到具体修订反馈后可在现有有界流程内改草案。这是修改任务，不重试原调用。审查后不能绕开不可变性检查。来源存在不等于语义支持，后者仍须对照真实轨迹核查。

## 二、减少审查协议负担，保留实际修订能力

保持同组节点与边联合审查。输出直接使用顶层 `u0/u1/...` 固定键，去掉 `reviews` 容器和按 keep/drop/revise 重复的 anyOf。经真实对照，节点进一步去掉分类动作：只提供最终完整正文、扁平时间字段、来源位置和理由；`text=null` 才表示撤销，程序比较前后正文/时间记录 keep 或 revise。这样避免“保留时哪些字段必须为空”和“修订时哪些字段必须填写”的额外决策。关系仍提供 keep/drop、来源、理由、已重审端点，supersedes 额外提供替代原句。来源枚举按各对象限定。

程序严格检查对象齐全、字段/类型、动作对应字段、来源范围、替代依据以及被修订/删除端点的关系。错误嵌套、漏项、未知字段不猜测修复；不保留旧输出协议兼容分支，不增加模型重试。解析后转为现有内部审查记录，让轨迹继续展示 before/after、来源范围和剩余待办。

审查从读者角度逐项检查：人物归属、否定、条件、数值、语气和事件时间。可能不等于计划，建议不等于承诺；明确承诺也不能被一律弱化。先呈现实际原文，再呈现待修草案，草案旁重列直接引用原句；重复材料计入实际模型预算，超限按现有规则分页。

时间表达必须是所选可见来源的原句（只容忍空白/大小写差异），程序校验原句；日期格式与区间仍由现有校验负责。实测仍有补入年份，因此增加必要条件：标准化日期的年份必须出现在所选原文里，发言时间元数据或 ref 名称不算原文明示。只有相对时间而没有明确年份时，保留原话和来源时间供外部解释，标准化字段留空；这是有意收紧日期推断，不是删除时间信息。年份存在仍不能证明年月日/事件对应正确，完整时间语义仍需审查。
