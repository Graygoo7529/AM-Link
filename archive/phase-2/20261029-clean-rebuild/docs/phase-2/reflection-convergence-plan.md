## 3. A：一个事实来源，三种不同状态

在最终序列化输入上收集全部实际正文范围：References的片段、Item正文、sources片段、显式Inspect页面。按`origin_ref/version/range`去重，不按来源ID整条去重；同一文本多处渲染只计算一次覆盖。仅有标签、摘要、hash或来源名字时不推断正文可见。

内部区分：

- **明确读取记录：**某次Inspect实际取得了哪个正文/来源范围。读取来源不等于读取节点全文。
- **本次可见范围：**最终请求确实包含哪些原文和正文。材料门槛使用这一集合，而非仅`disclosures`字段。
- **历史展示记录：**过去成功调用曾收到什么，用于诊断和避免无效重复；不自动授权本次写入。

保留原有片段和版本字段，不新增一套长期记忆。Inspect页面选择从“内部存在即不能读”改为“本次已完整展示且无新内容才无需重读”；隐藏、折叠后可恢复同页。Evict逐出活跃内容，必要的有界历史元数据可以保留；遗忘、删除、版本变化仍使相关读取凭据失效。

模型视图只保留有消费者的说明：语义ref、编号、正文/命中片段、来源及可读动作。当前同一正文同时位于text和text_fragment.text，候选页还反复携带长digest；应在不影响冻结解码和原文溯源的前提下消除重复，将完整机器账本保留在观测中。节省出的预算优先用于必要证据，不因此扩大循环。不能把摘要当成被删去全文的替代凭据。

必须覆盖最终序列化后再缩预算、短正文自动投影、同源不同窗口、重新加载、跨user、遗忘、版本变化。诊断账本和方法门槛不能各自计算一套覆盖。

## 4. B：读取服务于当前整理任务

### 4.1 默认先理解节点，再按需读长来源

Reflection Inspect的默认页优先目标MemoryItem正文；短正文一次完整展示，长正文明确列出缺页。来源页面继续由模型选择，附角色/时间/来源说明、命中片段和可读用途，不能只给hash与坐标。Search继续允许按检索问题优先读证据，不强行套用Reflection维护节点的顺序。

对每个待补材料显示本次有效引用位置、已读/可见正文比例、缺少的正文或来源页、实际可执行动作。仍由模型选择参数，系统不暗中执行一整串检索。

### 4.2 尽早形成可检查的变更意图

继续使用现有Mutation提案/校验反馈，不新增公开接口。模型应在理解本批新材料后提出有用变更；系统在提交前反馈具体缺项，并在本批loop内保留必要依据。不是先把所有旧节点读一遍，到第15轮才发现真正需要哪两项材料。

未提交提案可以作为本批的校验输入和保护目标，不能跨Add成为另一套待提交队列，不推进水位。保护最小必需正文/来源范围，不能因为保护一页而把全文及所有来源副本都固定在工作区。版本变更需重新校验。

保留足够的“补材料→下一主决策→提交”槽；在反馈时估计当前缺页的最低动作数。无法完成则明确报告不足，不继续把无效终结当成合法尝试。仍保持16轮和总截止边界，先验证流程而非加大上限。

### 4.3 有界动作记录

在记忆语境中放简洁结果记录：查询问题、范围、候选数量/语义引用、已读目标及范围、尚缺什么、剩余轮数。不保留整份模型对话，不请求内部思维链。相同范围/版本、相同问题、相同结果不能被误认为新进展。

优先让模型看到已完成的事实并减少重复查询；完全同样且无新状态的动作可复用确定性结果，但必须保留“没有新增材料”的标记。复用不是额外模型重试。若继续无进展，显式失败，不能自动no-op消费原文。

**已确认并实施：**旧资格范围经数据库确认完全为空时，用“已核验旧范围为空”的确定性凭据代替逐人物空Query。单独记录`scope_empty`，不伪造`query_performed`。一次查询没命中不等于旧库为空；非空旧范围仍执行原有身份探索。工程行为已验证，不把先前超时对照当作质量收益。

## 5. C：关系方向必须在写入前讲清楚

以小表和一组与数据无关的例子展示现有语法：

| 关系 | 合法方向 | 说明 |
| --- | --- | --- |
| about | fact/event → person/entity/concept/event | 谁的偏好、谁参加了什么事件 |
| contains | episode → fact/event | 哪段经历包含哪条事实/事件 |
| supersedes | fact→fact或event→event | 仅在原文明确替代时成立 |
| contradicts | 同类型fact或event之间 | 未解决的冲突，保留双方 |
| same_event_as | event ↔ event | 同一发生事项的不同记录 |

例如“某人喜欢某电影”用事实指向人物；不用person→person的about泛称人物关系。人物关系若有原文支持，可由一个独立可读事实连接双方。不得为了边数生成冗余节点或虚构联系。

已有fact/event通常只需要引用，不需要重新放进items；更新时建新节点并保留旧来源，禁止覆盖规则继续有效。

**已确认并实施的提交行为：**类型/方向错误、未知端点等在提交前有界反馈；剩余预算足够由模型修订，仍未合法则整批失败，WorkingMemory保留。确切重复关系保序去重。真实实验中Add确实仍有失败，因此当前仅工程实施完成，不能宣布方法通过验收。

不自动翻转关系、不猜测raw引用应指向哪个节点、不把非法字段修成成功。工具结构也要缩短和统一，Backlink不需要无意义的`page_position`；页参数仍绑定精确对象。协议简化与关系语义提示分开对照，避免无法归因。

## 6. D：让缓冲真正等待有用的积累

会话连续前缀、容量压力及已冻结水位继续是确定性约束。`update the`、`instead of`等仅表示可能发生变化，不能把修改程序、刷新缓存等技术叙述直接判为记忆更正。

建议先取消宽泛词面命中对普通积累门槛的无条件绕过；将命中原句与候选变更对象作为维护语境提示。对于确有立即处理价值的更正/遗忘，保留明确来源和作用对象的路径，不以关键词触发删除。若需要门槛前语义判断，只对含糊但有紧迫可能的线索增加一次有界模型决策，并单独报告成本；不默认每Add额外调用一次模型。

同历史、同切分对照当前策略与修正策略：记录触发原因原句、首次整理前Add数、批次跨度、跨批主体复用、有效关系和pending水位。先证明避免误触发且没有漏掉明确变化，再调8条/6000字符等参数。不让Search承担收尾Reflection。

## 7. E：扩大的是机制覆盖，随后才是题数

先用公开小切片复验L04集合与人物、B01更新、B02冲突、P01关系，再加入L02/LM01时间、PV01主体归属、PV04遗忘。切片由catalog绑定；gold只给后验评估，正式方法仍只见Add原文与Search问题。

这轮必须有足够干扰候选，使生产阈值自然触发Select；必须有符合现有规则的复杂问题触发查询扩展。不能把“调用次数为0”解释成这些算子已验收。记录分支合并、Select前后候选及位置、实际读取范围、BFS边和最终组成员。

先做两种分开的实验：

1. **Add构图实验：**同历史独立数据库，人工核对新旧主体、来源、关系方向、事实覆盖/重复、触发与完成水位。不以边数越多越好。
2. **固定图Search实验：**复用已核对的真实图，冻结数据/模型/输出字符预算，检查`Inspect→新ref→Inspect`、`Backlink→Select→Inspect`及最终证据闭合。手工控制图只验证工程，单独标注，不能冒充真实构图。

首批建议每条件3个独立有效运行；网络失败、工具协议失败、材料门槛失败、语义错误分开。小批按明确总调用/输入预算启动，例如每批最多200次请求、500万字符，达到上限后报告状态，不自动重跑。得到可用改进组输出之前，不扩大20/100题。

转入20题的门槛：指定反例全通过；所选小切片没有未解释的Add失败；至少一条人工核对有效的跨批关系实际用于Search；真实Select及查询扩展都执行过；支持证据在每一阶段可追踪；正确性不能依赖Answer猜测。再做20题覆盖集合、时间、更新、冲突、人物与拒答；各项达标后才100题。报告成功Add覆盖、检索证据召回、完整链、独立Answer诊断（若运行）、延迟/调用/费用，不用HTTP200替代质量。

## 8. 可行性核查

现有原文、来源范围、版本、引用映射、请求水位和span足以完成这些改进，无需修改公开Add/Search形状或长期记忆类型。主要变更集中在engine/projection/grounding/reflection_policy/reflection及对应测试；展示侧消费同一账本，避免再维护一套逻辑。

本次回读TinySoul的`prompts/plugins/reflection.py`、`plugins/reflection/turn/prompts.py`与`kernel/retrieval/selection.py`：它把现有记忆的先读后写、固定处理范围及Session/Workspace/TurnTrace明确交给模型。可借鉴的是可执行的小步任务、可读语境和结果反馈。其允许部分写入保留等行为与AM-Link当前原子批次/水位不同，不直接移植；也不引入其额外模型、rerank或内部重试。

风险是保护内容过多、输入结构重复和过严门槛增加失败。用实际序列化预算、最小目标范围、早期提案检查和明确终结解决，不能靠取消来源检查。新增事实必须区分已有代码、本地反例、真实实测、推测与待确认行为。
