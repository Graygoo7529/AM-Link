# 证据可见性与首次草案：下一轮执行计划

日期：2026-10-26。基线：`6e34e1f`。承接[跨数据集计划](2026-10-24-broad-method-improvement-plan.md)的 A/B/C/D/E 包。本轮记录实施、实测和未完成项，不将局部成功视为整体方法验收。

## 方向—设计—验证—分析

| 方向 | 本轮设计 | 验证与判定 |
| --- | --- | --- |
| B：模型实际看到什么 | 在相同字符预算内，以完整命中窗口的区分度选择片段，替代“遇到第一个词即截取”；多个问题分支共同选择互补来源/范围。短来源优先保持完整。原文坐标、日期、角色及遗漏账本沿用现有协议。查询扩展拆出互补信息需求，不自行确定相对时间或补造人物/数值。 | 冻结 LM4 候选、问题和预算比较前后片段；检查金额、时间、主体、否定的可见性。真实 Select 单独对照，记录选择、排除和成本；默认触发阈值先不变。 |
| A：先有草案再查证 | 首次节点与关系任务分开；先暂存节点/身份/来源提案，针对提案补旧材料，再单独生成有支持的关系。必要时允许返回节点阶段。始终一次提交节点、边与水位，未通过门槛不能 no-op。 | 回归覆盖草案不入库、失败重放、旧目标缺读、关系反馈与原子提交。新库真实样本检查首次提案前阅读、成功率、主体与关系质量。若本轮不足以完成整个协议，明确保留待实施状态。 |
| C/D：支持与闭合 | 将“来源存在”“片段确实展示”“语义支持”“最终保留”分开。审计重复派生节点占 top-k、图路径实际贡献与原文闭合。 | 相同库 Search 与新库端到端分别报告；不以来源闭合等同正确答案，不以边数等同有效图。 |
| E：保留集 | 修复例用于定位；另用不同人物/历史、任务类型和至少一个不同数据来源复验，保存输入/源码哈希及失败。 | 所有尝试进入台账；辅助证据窗口与完整历史分开。模型/网络失败不在内部重试，不删除失败成绩。 |

## 执行顺序

1. done：确认用户提交与历史临时产物状态，重读最新计划和真实反例。
2. 实施 B，先本地坐标/预算/互补范围回归，再冻结候选调用真实 Select；若片段仍漏关键信息，明确解释后迭代，不能仅提前 Select。
3. 根据新轨迹实施 A 的可闭合范围，保持公开 Add/Search、存储边界与无内部重试原则。
4. 新库与冻结库分组验证，更新 DESIGN、实施报告、案例评注和索引，核对计划完成范围。

可检索最低 episode、WorkingMemory 缓冲、独立 Search loop、默认确定性装箱和模型限制保持现有约定。LLM 装箱只作为离线实验；本轮不部署，不自动提交。

## 本轮实施核对

- done：B的窗口/来源排序、短消息保护、多来源Select输入、数值扩展约束；本地金额/日期/否定/Unicode/预算回归及冻结库真实调用。LM4三种金额全部可见，但Select仍排除关键episode，质量目标partial。
- done（实验）：A的首次节点草案、具体材料待办、关系阶段、受控返回修订、最终原子提交、失败重放；新增默认关闭开关。关系方向由工具参数按节点kind限定。两轮真实失败后修复重复草案与冗余布尔值，完整材料仍未验收。
- done：根据完整人物材料修复短中文支持说明长度偏差，以及已展示来源被缓存折叠后的引用校验断点。来源存在与语义支持继续分开。
- partial：C的逐句支持范围、人物归属与近义重复；D的Select集合完整性、图增益与最终装箱对照。这轮没有启用模型装箱或提前Select默认值。
- done（研究扩展）：新增三个LoCoMo人物历史和一个完整PerLTQA人物记录；开发例、辅助窗口和完整记录分栏。未达到扩大总体准确率评测/部署验收门槛。

下一包优先：在关系阶段发现端点缺失时，只让模型补具体节点/修具体字段，避免要求重写整份草案；保留已验证部分及其来源范围。与此同时固定LM4候选做证据集合选择对照，审计重复fact与episode取舍。新方案必须保留原子提交、未满足材料门槛不能no-op、无内部重试；扩大完整历史之前先在不同人物/文档上验证。
