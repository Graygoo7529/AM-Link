## 方向与设计

目前最值得检验的不是单一检索分数，而是四个连续断点：新旧记忆是否被正确区分；工作记忆是否有足够依据转成有用结构；查询和多跳是否找到互补证据；Search 返回前是否把必要来源完整闭合。2026-10-23 的真实运行中，结构化节点/关系的主体和来源不稳定，历史图 Search 有一次因模型输出截断失败，受限模型装箱漏掉一个已标注来源。这些是已观测个例，不代表跨任务发生率。

本轮按下列可检验方向推进：

| 方向 | 设计假设 | 可观测的否证条件 |
| --- | --- | --- |
| 写入认知负担 | Reflection 先形成少量可核对的节点/事实提案，再单独处理关系边；原子提交仍一次完成。分步阶段只保留本批暂存提案，不新增持久记忆类型或公开 API。 | 任务拆分未减少 schema/论元错误，或增加的步骤造成更多超时、错误来源与无意义节点。 |
| 探索待办 | 提案校验产生针对具体节点、来源、身份和关系端点的待办；每次探索后明确标记哪些已满足、还缺什么、最低还需几步。只保护待办所需范围，不将整个来源或历史对话固定在 context。 | 轨迹仍反复查询/Inspect 已完成材料，或失败前没有清晰剩余待办和停止原因。 |
| 来源与语义支持 | 节点正文来源、关系边直接支持来源分别记录；关系说明必须从被引用原文中可读，不能只因两个节点共同出现就建边。类型/方向校验继续阻止非法提交。 | 来源可见但人物归属、方向、时间、关系含义仍与原文不符；支持片段无法解释边的语义。 |
| Search 路径与闭合 | 用具有已核验图结构的样本和自然构图样本分别核查 Query 分支合并、Inspect/Backlink 多跳、Select 保留、最终证据组及来源闭合。装箱继续默认确定性，模型装箱仅冻结输入离线对照。 | 任一必要来源在召回、Select、Inspect、BFS 路径或最终输出阶段消失却没有对应账本；人为图结果被误报为自然构图成绩。 |
| 广泛样本覆盖 | 将每次靶场运行固定到一个案例任务，以数据集、任务类型和记忆难点分层；训练/修复样本与复验样本分开。报告所有选择、排除、失败和调用量。 | 只重复 LoCoMo L04、BEAM B01、PerLTQA P02 等优先案例，或只统计成功运行。 |

### Reflection 的候选分步协议

现有 `reflection_mutation` 同时要求模型理解新旧记忆、构造多类型节点、人物身份、遗忘授权、时间字段、关系方向与来源支持。候选改进是把内部工具拆成两个认知任务：

1. `reflection_items`：只提出节点/遗忘提案，带变更类型、精确来源和所需旧目标；系统校验后给出待办。
2. `reflection_relations`：基于已暂存节点与已加载旧节点，单独提出关系；每条边单列支持来源及语义说明，系统反馈端点类型、方向和直接来源缺口。
3. `reflection_commit`：只有两部分都校验通过后才一次性提交节点、边、遗忘与处理水位。空关系集合可显式提交；真正 no-op 仍独立于失败提案。

提案暂存在本次冻结 Reflection Workspace 中，进程失败时仍按现有水位和幂等规则重放；不提前写入节点或移动水位。不得将来源存在误认为语义正确，也不得让来源/关系说明变成无法追溯的自由文本事实。

首轮已确认混合Mutation产生非法方向、虚构端点和无效阅读。当前已落地**出错后的关系单独修复**，以及身份/不可变性/类型的阅读前预检；上述三个工具完整协议仍是下一实施包。真实运行常撤回全部边，说明只拆修复阶段不够，必须在首次节点草案阶段考虑确有来源的person/entity导航端点，且允许因关系任务返回补节点。

首轮候选为 catalog 中 21 个独立案例，跨 8 个准备数据包/版本与 7 类数据来源。每个运行采用独立数据库，固定当前版本、chunk-size 6、top-k 5、scope、radius 和模型配置；答案、rubric、gold evidence 不进入 Add/Search。先执行 plan-only 校验，记录切片是否保留作者证据；被切片剔除证据的样本不计入召回分母，但仍可作无评分运行轨迹诊断。

| --- | --- | --- |
| PerLTQA | p1、p2 | 人物关系、来源归属、跨话轮关系方向 |
| BEAM | b1、b2、b3 | 新旧值更新、冲突保留、事件先后与时间字段 |
| LoCoMo | l1、l2、l3、l4 | 跨会话实体、时间/计数、长程组合、证据窗口覆盖 |
| LongMemEval | lm1、lm2、lm3、lm4 | 跨会话事实、偏好/知识变化、拒答、复合来源闭合 |

| CL-bench Life | c1、c2 | 材料驱动工作、约束/流程是否能压缩成可执行记忆 |

plan-only 首轮发现 b3 与 pv4 没有可用 turn 锚点，因此按 catalog 绑定记录完整历史运行；这不是切片遗漏证据，而是此类案例本来就没有锚点。其余 19 个案例均保留作者标记的证据。若案例切片为空、绑定失效或作者证据不完整，保留原案例 ID 并按数据包选择可评分替代题；不能为了凑数静默改成 full 或删除失败样本。首轮全矩阵覆盖后，依据实际成本再运行实现组；改动组中至少一半案例不参与定向修改。若真实请求超时/供应商失败，单独列出，不进行靶场内部重试。

每个运行至少汇总：Add 成功/失败数、持久 episode/语义节点/关系数、Reflection 轮次与每种工具次数、schema/证据/关系失败原因、候选/引用可见字符、明确读取范围、工作区待办/完成情况、Search 查询分支及合并数、Select 前后集合、Inspect/Backlink 路径、每条标注证据在链路中的最后出现位置、最终来源闭合和字符覆盖、实际模型请求/输入输出用量/端到端耗时。缺少埋点记 `unknown`，不按零计。

## 方向—设计—验证—分析循环

| 轮次 | 工作 | 退出条件 |
| --- | --- | --- |
| 0. 计划/数据质检 | 固定分层矩阵；对 21 个样本运行 plan-only；核验选中历史、Add 数、作者证据保留和查询数量。 | done：形成可运行及不可评分清单；运行输入哈希冻结。 |
| 1. 当前版真实基线 | 在多数据集独立运行当前提交；对全部运行解析同一观测标准，归纳最常见失败阶段。 | 关键失败可定位到 Add 构图、旧记忆探索、Query/Select、BFS 或闭合，不以少数成功例代替。 |
| 2. 低风险实现 | 先修有直接证据的 schema/反馈/预算账本缺口；如混合 mutation 确为主要问题，再做临时分步提案；来源与关系支持分账。 | 新回归验证行为边界；DB/API 不变；同一反例不会靠放松证据门槛通过。 |
| 3. 定向验证 | 用参与设计的案例复测错误机制，另选跨数据集保留集；必要时在一份核验图副本上单独测试 Select/Backlink/Inspect/装箱。 | 原失败机制被关闭；新缺陷能被观测解释；人工图结果与自然构图结果分栏。 |
| 4. 分析和迭代 | 对照基线/改动组，按来源与任务类型检查收益、退化、成本和未知项；只将有跨样本证据的修复推进下一轮。 | 决定继续修复、扩大到20题或暂停；没有足够独立成功样本时明确保持“未验收”。 |

采用两个分开的评分面：**Add 构图**看原文保真、必要语义节点、人物/来源归属、关系有效性、重复/遗漏、跨批水位；**Search 证据**看候选覆盖、Query 分支、Select 保留、图路径、来源闭合和答案材料完整度。Answer 可作为独立诊断层，不把 Answer 猜中当作 Search 完整的证据。自然构图和人工核验图必须分开报告。

## 风险与明确边界

- 真实模型运行只使用当前用户授权的公开样本切片和配置端点；单次运行限定调用/输入预算。凭据只从本机忽略的私有环境文件读取，不写入研究工件。
- 不引入内部网络重试、后台补偿、超出当前公开 Add/Search 的回答功能或部署。
- 不因运行数量多就推断总体准确率；19 个案例是机制覆盖集，不是随机代表性抽样。
- 不把边数量作为图质量目标；每条边要与具体支持来源和语义匹配。
- LLM 装箱默认仍关闭。只有多数据集冻结样本上优于确定性方案且满足来源闭合门槛，才另立计划讨论默认切换。
